# 事事顺 × AI 协作说明

一句话：**git 负责「事实」，AI 负责「归纳」，人负责「拍板」。**

## 1. 协作链路

```
本地 commit ──post-commit hook──► commits-YYYY-MM-DD.tsv
                                        │
                              sync.sh prepare
                                        │
                        过滤（我的提交 / 已处理 / 时间窗）
                                        ▼
                                  digest.md（按仓库、带时间与参考工时）
                                        │
                         AI：归卡 → 聚功能点 → 摊工时 → 写 ≤20 字
                                        ▼
                        事事顺 add_log / update_log
                                        │
                        日志 id 写回 logmap；提交标记 processed
```

| 角色 | 负责 | 不负责 |
|------|------|--------|
| 机器（hook + 脚本） | 采集提交、去重、算时间跨度、生成 digest、幂等标记 | 判断业务含义 |
| AI | 归卡、聚功能点、概括成 20 字、分摊工时、判断是否有信息量 | 编造提交、改状态、改别人的卡 |
| 人 | 定规则、建卡、补非提交工作、拍板完成 | 逐条整理提交 |

## 2. AI 在这条链路里只做四个判断

1. **归卡**：今天的 `mine=true` 里选一张（repoProjects 映射优先，其次关键词）
2. **聚功能点**：同模块且时间区间重叠 → 合并，工时只算一次
3. **摊工时**：按功能点的时间跨度分摊，合计对齐 digest 的参考工时
4. **写内容**：≤20 字、最多 1 个 hash、不复制 commit 原文

四个判断都有硬约束兜底：工时由脚本算、去重靠 `processed`、合并靠 `logmap`、`complete` 保证幂等。AI 的自由度被限制在「理解与表达」，而不是「记录事实」。

## 3. 优势

- **事实可溯源**：每条日志背后有提交，digest 留档，能回到具体 hash
- **幂等**：重复跑不会多记；写一半失败可补跑
- **低打扰**：没有提交时只回一行
- **零服务**：纯 shell + 本地文件，没有数据库、没有常驻进程
- **跨平台**：Git Bash / Linux / macOS 同一套脚本
- **工时自动累积**：同一天同一功能点走 `update_log`，不产生第二条

## 4. 劣势与边界

| 边界 | 影响 | 缓解 |
|------|------|------|
| 只能看到**本机** commit | pull 下来、别的机器提交的会漏记 | 目前靠人工补，可加兜底扫描 |
| 卡片按天 | 跨天补录要传 `logDate`；容易写错卡 | 已加「每轮重查今天卡片」规则 |
| 工时是估算 | 9:00 首轮基线、午休扣除都可能失真 | 允许人工改数字 |
| 归属靠判断 | 没有映射时可能挂错卡 | `repoProjects` 配置可提升准确率 |
| 定时任务是会话级 | 新会话要重建，应用关闭不触发 | SKILL 里有重建参数 |
| 20 字上限 | 复杂工作会被压缩 | 细节留在提交与笔记里 |
| 非提交工作 | 会议、梳理、答疑没有 git 记录 | 必须人工补记 |

## 5. 改进路线（按「代价小、收益大」排序）

### P0：1 小时内能做完，收益最明显

| 改进 | 代价 | 收益 |
|------|------|------|
| 1. `config.sh` 填好 `repoProjects` 映射 | 5 分钟 | 归属准确率立刻提升，减少挂错卡 |
| 2. 写完日志回读 `list_logs` 校验内容与工时 | 10 分钟 | 写错卡/写错字当场发现 |
| 3. `prepare` 增加 pull 提交兜底扫描（开关） | 30 分钟 | 补上「别机提交」的漏记 |
| 4. digest 预给出功能点候选（按时间聚类） | 1 小时 | AI 少一次猜测，分组更稳定 |

### P1：半天级

- 卡片映射从「仓库→项目」细化到「仓库→卡」
- 用历史日志校准工时系数（按项目/类型）
- 日终自动生成总结草稿，写入项目工作内容

### P2：多天级

- 多机同步 journal（提交到 git 或对象存储）
- 引入 LLM 聚类替代时间规则，关联 issue / PR

**结论**：先做 P0 的 1+2+3，约一小时，一次性解决「漏记、挂错、算错」三类主要问题；P2 的收益在团队规模变大后才显现。

## 6. 使用建议

- **提交信息写「做了什么」**，别写 `update`、`fix bug`；AI 的概括质量取决于输入
- 每天确认一次今天的卡是否存在，没有就先建
- 非提交工作当天口头补一句，别攒到周末
- 每周抽查一天，对一下日志与实际工作

## 7. 什么情况下不适合用

- 主要工作不在 git（会议、文档、测试为主）
- 多人共用一台机器、都要记工时
- 对工时精度要求到 0.1 小时
