## 第 0 章 适用与基础

### 0.1 适用范围

本规范适用于B端Web管理页面、工作台、表单与复合组件。设计基准为1440px，完整桌面任务支持宽度≥1024px；窄屏适配按4.3。移动端App、小程序与大屏使用各自规范。

### 0.2 设计体系

- 组件采用[Ant Design](https://ant.design/components/overview-cn/)，默认亮色主题；设计语言参照[Ant Design design.md](https://ant.design/design.md)。
- 组件属性与主题配置以项目安装版本为准；本文工程参数参考antd6.6.8。图标使用匹配版本的`@ant-design/icons`；Pro系列为独立依赖。
- 页面统一使用语义Token、对应组件的状态与交互，不以同色值合并不同语义。

### 0.3 规则优先级与强度

| 强度 | 适用原则 |
| --- | --- |
| 强制 | 数据正确性、权限、可访问性与任务完整性必须满足 |
| 默认 | 无特定要求时采用；局部调整需明确用途与适用范围 |
| 可选 | 仅在业务任务、数据或空间需要时使用 |

明确的页面需求与有效项目配置优先于通用默认值；同一页面的同类组件保持一致。局部样式调整不得破坏强制规则。

### 0.4 页面业务范围

- 页面围绕主要角色和主任务组织信息，仅提供完成任务所需的模块与操作。
- 对象具有稳定标识；字段明确类型、单位、必填、校验与缺失值，状态明确成立条件、退出条件和允许操作。
- 指标、图表与额外业务模块须有明确用途和数据口径，不为填满布局新增内容。
- 操作入口必须对应真实能力，说明作用对象、成功结果、失败恢复与返回路径；示例数据不得伪装成实际业务结果。

## 第 1 章 设计原则

设计遵循自然、确定性、意义感与生长性。

### 1.1 自然

沿用用户熟悉的输入、导航、表格及反馈方式，按工作任务组织信息。默认复用Ant Design组件，不为普通操作重新发明手势或视觉符号。提供真实标签、可预期的键盘行为和合理的内容顺序。

### 1.2 确定性

当前范围、选中对象、保存状态与下一步清楚可见。默认、悬停、聚焦、禁用、加载及错误按适用语义区分；不能把处理中或写入结果未知显示为成功。保持同类任务的布局、文案及操作位置一致。

### 1.3 意义感

视觉强调服务于完成工作目标。页面围绕主任务提供必要信息与反馈；指标、图表和装饰按任务启用，缺少真实口径时不编造。成功反馈说明实际完成的动作。

### 1.4 生长性

通过Token、基础组件和可复用组合支持业务增长。扩展需有清楚边界，允许增加字段、长文案、更多数据与角色，不靠固定样例尺寸维持页面。业务流程与外观实现分别维护。

### 1.5 信息优先与克制表达

先保证标识、状态、数值和操作可读，再考虑装饰。默认14px正文、400正文与600标题，静态容器以背景、边界和间距组织层级。渐变、大插画和阴影只有在传达含义时使用。

### 1.6 主次与一致性

默认每个页面常态只突出一个主要动作。Modal打开后由当前任务承担主要动作，背景不可操作。分区确有独立目标时可设置分区主操作，不能把每个按钮组都作为增加主要按钮的理由。具体按5.2.1。

### 1.7 就近反馈与可逆性

错误靠近字段或失败范围，操作结果对应具体对象。能撤销的优先撤销；不可逆操作说明对象、数量与后果。关闭编辑、返回列表和请求失败时保留用户已输入的信息与必要上下文。

### 1.8 适配与可达

对目标屏宽、长文案、键盘焦点和文字缩放提供完整任务路径。状态不只靠颜色，必要信息不能仅靠hover。文字与背景需满足任务的可读性和对比度要求，必要时通过主题统一调整。

## 第 2 章 设计基础（Foundation）

### 2.1 色彩

- 采用Ant Design的品牌/功能/分类/中性色职责；品牌主色`colorPrimary`，成功/警告/错误/信息分别使用`colorSuccess/colorWarning/colorError/colorInfo`。
- `colorBgLayout`是页面底色；`colorBgContainer`是内容表面；`colorBgElevated`是浮层表面。相同HEX不能作为合并语义的理由。
- 输入框默认outlined白底；表头使用独立`Table.headerBg`，不让“灰色表头”和“白色输入框”共用一个背景Token。
- 运行时文字使用rgba语义色；白底合成HEX不直接用于带色背景。
- 分类预设色只用于分类、Tag和图表；风险状态使用功能色，并同时提供文字或图标。
- 小字号文字、按钮文字与背景必须保持足够对比；通过全局或组件Token统一调整。

### 2.2 字体与排版

- 正文14/22、辅助12/20、区块标题16/24、页面标题20/28；完整层级见3.3.7。
- 默认系统UI字体栈，正文400、标题/表头600。选中态依颜色和下划线表达，不额外把普通Tab文字变成标题字重。
- 不把13px代码字直接当辅助说明字；接口框架内默认避免700以上粗体、细体及装饰性斜体。
- 比较数字使用`font-variant-numeric: tabular-nums`，数字列右对齐。编号、电话和日期作为标识文本处理，保留完整获取路径。
- 按中文、英文、长词、文字放大及不同平台字体回退验证换行；截图中的字体宽度不视为跨平台常量。

### 2.3 间距与栅格

- 4px基本网格；常用间距4/8/16/24/32px。SDK另有12px、20px等派生值，项目只在明确用途使用，见3.3.8。
- Card body默认24px；Input内距采用组件值，不为凑网格取整。单行选择器左右留白12px，见5.3.3。
- 布局使用24列Ant Design Grid；gutter项目默认12px。CSS Grid亦可使用，只需记录跨列关系，不能把12列设计直接传成24栅格中的完整一行。
- 卡片宽度由轨道、跨列和min/max约束计算，允许小数；458/459px等计算结果本身不是违规。
- 同类元素对齐，模块、表单字段与分组分别使用对应间距；主次区域可不同宽。组件内部padding、表格cell padding与外层Card内距避免重复。

### 2.4 圆角、描边、阴影与层级

- 控件和Tooltip圆角6px，Card/Modal/Popover圆角8px，小Tag圆角4px；具体用途见3.3.9。
- 默认边界1px；活动Tab下划线2px、焦点外框与SVG笔画分别处理。
- 静态表面优先边界和色差，浮层才使用对应阴影；Card不默认新增hover悬浮。现成组件自身过渡与效果按版本复用。
- 同一视觉角色不随页面任意改变半径；圆形头像、Badge点和必要的表格裁切按组件语义处理。
- 层级以官方Token及上下文管理，不靠随意放大z-index。Modal/Drawer、内部选择浮层与当前焦点必须协调，见3.3.13。

### 2.5 图标

- 优先使用与工程版本兼容的`@ant-design/icons`。图标外观尺寸与可点击区域分别确定，常用14/16/20/24px按组件和任务选择。
- 同一含义使用同一图标；沿用官方Outlined/Filled/TwoTone资源，不全局重绘笔画。双色图标的主色与主题统一。
- 纯图标操作必须有可访问名称；Tooltip仅补充可见解释，不能替代控件名称。
- 箭头使用正式图标；不以Emoji、字符或旋转线段近似替代。装饰SVG不进入Tab顺序，必要时隐藏于辅助技术。

### 2.6 插画、空状态视觉与头像占位

- 默认空态使用Ant Design Empty，流程结果使用Result；按首次为空、筛选为空、失败和无权限分别配置内容。
- 业务插画与图片需符合页面用途和统一风格。
- 插画用于有意义的空态或欢迎场景，不抢占任务区。无数据时不保留无意义大图占位。
- 头像可用图片或首字母；默认颜色按用户ID稳定映射，文字和底色对比需可读，不使用随机刷新颜色。

### 2.7 动效

优先复用现成组件动效。页面自定义过渡引用`motionDurationFast/Mid/Slow`，默认100/200/300ms；标准缓动引用`motionEaseInOut`，值为`cubic-bezier(0.645, 0.045, 0.355, 1)`。

- 只过渡所需属性，页面不新增transition:all或大列表逐项入场。
- 动效传达状态和空间关系，不推迟必要反馈。无法获得特定动作Token时使用Mid及官方缓动。
- 响应`prefers-reduced-motion`，减少非必要位移、闪烁及循环，保留静态状态和文案；可通过`theme.token.motion=false`关闭组件动效。
- 不把默认动画当成请求完成时长；耗时任务使用真实阶段或进度。

### 2.8 图片与媒体

| 项 | 规则 |
|---|---|
| 比例 | 缩略图固定 16:9 / 1:1，容器预设比例，**禁止图片拉伸变形** |
| 圆角 | 跟随所在容器圆角 |
| 懒加载 | 视口外图片按需懒加载；首屏关键图不延迟，预留尺寸避免跳动 |
| 占位 | 加载中用 `--ui-color-fill-quaternary` 占位块 |
| 失败兜底 | 加载失败显示占位图标 + 类型说明，**禁止**显示破图 |

## 第 3 章 Design Tokens 与命名

### 3.1 三层 Token 结构

Ant Design以Seed → Map → Alias形成派生链，组件再消费全局Token及自己的Component Token。[官方主题说明](https://ant.design/docs/react/customize-theme-cn/)为工程依据。

```text
Seed：colorPrimary、fontSize、borderRadius等设计意图
  ↓ defaultAlgorithm / darkAlgorithm / compactAlgorithm
Map：颜色梯度、尺寸、背景/文字层级
  ↓ 语义用途映射
Alias：colorText、colorBgContainer、colorBorder等消费语义
  ↓
Component Token：Table.headerBg、Card.bodyPadding等
  ↓
实际组件与页面；项目CSS别名仅作适配
```

Seed的`colorBgBase/colorTextBase`用于派生，不直接代替页面的`colorBgLayout/colorText`。组件覆盖是否重新派生取决于组件级algorithm配置，不能假设改任一Alias都会重新生成整个主题。

### 3.2 命名规则

#### 3.2.1 官方设计别名与SDK名字

design.md采用`colors.* / typography.* / rounded.* / spacing.*`描述设计语言；React主题配置使用Ant Design实际Token名，两者不是同一API。

| design.md语义 | SDK或组件Token | 项目CSS别名 |
| --- | --- | --- |
| colors.primary | colorPrimary | --ui-color-primary |
| colors.surface | colorBgContainer / colorBgElevated，按表面角色 | --ui-color-bg-container / --ui-color-bg-elevated |
| colors.surface-layout | colorBgLayout | --ui-color-bg-layout |
| colors.surface-container（#FAFAFA） | Table.headerBg等浅表面；不能误映射colorBgContainer | --ui-color-table-header-bg |
| colors.on-surface | colorText（保留rgba） | --ui-color-text |
| colors.on-surface-variant | colorTextSecondary | --ui-color-text-secondary |
| colors.outline / outline-variant | colorBorder / colorBorderSecondary | --ui-color-border / --ui-color-border-secondary |
| rounded.DEFAULT / rounded.lg | borderRadius / borderRadiusLG | --ui-radius-control / --ui-radius-card |

浅填充、页底、表头与输入背景按用途分别映射，不按颜色相似或无语义的序号推导。

#### 3.2.2 通用命名格式

SDK保持官方camelCase；组件覆盖写在`theme.components.ComponentName`。项目CSS使用`--ui-{类别}-{用途}`，例如`--ui-color-text-secondary`。布局间距使用数值名`--ui-space-12`，避免把项目sm与官方sm误认为相同。

每项记录来源、版本、算法、用途和是否覆盖。定义了`--ui-*`不会自动改变Ant Design组件；动态主题的CSS别名必须同步实际解析结果。

#### 3.2.3 档位词表与SDK映射

Button/Input/Select等通用尺寸使用`small / medium / large`；`default`不是这些控件的通用尺寸名，省略size可采用组件默认。控件默认medium，Table默认large。

Drawer另有`size="default" / "large"`及数字/字符串；这些size属于抽屉宽度，不等同控件高度。Card默认medium，提供small；不同组件各查类型。`controlHeightXS=16`是Token，并不意味着Button有可用的`size="xs"`。

| body-sm | 12/20 | 400 | 辅助说明、Tag |
| code | 13/20 | 400 | 代码内容 |

默认系统字体栈与代码字体见附录A。字号与行高分别定义；lineHeight为比例，例如14px×1.571428…=22px。标题字重600使用`fontWeightStrong`；字体回退和缩放后仍需保持可读。

#### 3.3.8 间距 Space

间距使用4/8/12/16/20/24/32px数值别名，按场景分配。

| 场景 | 默认值与用途 |
| --- | --- |
| 图标与极近辅助信息 | 4px或源组件值 |
| 操作按钮组 | 8px |
| 表单标签到控件 | 12px，保留项目默认；覆盖Form默认垂直标签内距 |
| 相邻功能区块、分类面板与列表 | 12px，项目覆盖，见3.3.8.1 |
| 筛选项行/列间隙 | 12px，项目覆盖，见8.2.3 |
| Modal外壳垂直/水平内距 | 20/24px，内容区不重复叠加同一份内距 |
| Card body | 24px，默认medium |
| 卡片/页面主要区块 | 12px，项目默认 |
| 长表单组间 | 32px，项目默认 |

15px按钮和11px输入padding是源组件几何，不能统一取整。已有组件Token能表达时优先用Token，新增页面不随意造13px/17px间距。

##### 3.3.8.1 模块间距12px

同级模块之间的水平、垂直间隙默认12px，不因宽屏自动放大。

| 关系 | 默认值 | 实现 |
| --- | --- | --- |
| 页面标题与首个内容模块 | 12px | 所属父容器gap或单侧margin |
| 分类/树面板与列表、并排Card、指标卡、工作台模块 | 12px | Grid/Flex gap或Ant Design gutter |
| 同列相邻Card、筛选区→结果/工具栏→表格→分页 | 12px | 每个边界只由一处负责留白 |
| 筛选字段的行间与列间 | 12px | 同一等宽栅格的row-gap/column-gap |

CSS统一使用`--ui-layout-gap: var(--ui-space-12)`，`--ui-grid-gutter`引用该值；Ant Design布局API使用对应12px项目值。这里的12px是目标CSS间距，允许浏览器小数舍入，不允许无依据改成16/24px。不要将父gap与相邻元素margin叠加成24px；空间不足优先换行或减少列数。

本条只覆盖模块间隙与筛选栅格，不对所有CSS中的gap/padding/margin做全局替换。页面外边距仍按4.1.2/4.3，Card body默认24px；普通表单标签12px、字段24px、分组32px按7.1.2，按钮组8px及源组件内部几何继续沿用。表单网格的字段间距不因模块gap改动自动压缩；确需紧凑变体时明确用途和适用范围。

#### 3.3.9 圆角 Radius

| 对象/Token | 默认值 | 说明 |
| --- | --- | --- |
| borderRadius / 控件 | 6px | Button/Input/Select |
| borderRadiusLG / 表面 | 8px | Card/Modal等 |
| borderRadiusSM / 小标签 | 4px | Tag |
| Tooltip | 6px | 继承控件圆角 |
| Popover | 8px | 继承表面圆角 |
| borderRadiusXS | 2px | 特定内部细节，非全部控件 |
| rounded.xl | 16px | 官方设计词表，不作为普通按钮默认 |
| rounded.full | 9999px | 圆形头像/点/徽标用途 |

未列明的变体使用对应组件Token。表格可有外层圆角而内部单元格方形，不能根据一条“表格方形”清除整个组件圆角。

#### 3.3.10 阴影 Shadow

| 角色 | Token | 说明 |
| --- | --- | --- |
| 静态内容 | none，项目默认 | 不默认让全部卡片悬浮 |
| 轻抬升 | boxShadowTertiary | 三段轻阴影 |
| 标准浮层 | boxShadow / boxShadowSecondary | 默认Light解析同值，语义仍保留 |
| Card抬升 | boxShadowCard | 组件专用，按任务启用 |
| 贴边Drawer/溢出提示 | boxShadowDrawer* / boxShadowTabsOverflow* | 方向与条件分别管理 |

具体可复制值见A.2。固定操作列的分隔阴影只在存在未显示的滚动内容时出现，项目行为见8.1.4；不能用永久box-shadow假装表格仍有内容。

#### 3.3.11 动效 Motion

| Token | 默认值 | 典型用途 |
| --- | --- | --- |
| motionDurationFast | 0.1s | 轻状态变化 |
| motionDurationMid | 0.2s | 组件内部变化 |
| motionDurationSlow | 0.3s | 较大表面进出 |
| motionEaseInOut | cubic-bezier(0.645, 0.045, 0.355, 1) | 无更具体曲线时使用 |

具体组件还会使用motionEaseOut等官方曲线，不统一重写；减少动效按2.7。

#### 3.3.12 断点与栅格

xs<576、sm≥576、md≥768、lg≥992、xl≥1200、xxl≥1600。`screenXS=480`是另一个全局Token，不表示Grid的xs只从480开始。标准24栅格，gutter项目默认12px。

完整桌面任务目标≥1024px；1024是本项目支持阈值，不新增为Ant Design官方断点。具体行为统一在4.3维护。

#### 3.3.13 层级 z-index

`zIndexBase=0`、`zIndexPopupBase=1000`。组件还有自己的zIndexPopup及上下文派生，不将所有下拉统一固定为1000。

页面sticky使用10并受当前任务遮罩约束；Modal/Drawer遵守组件的上下文顺序，内部Select/DatePicker/Tooltip归属当前任务。先查Portal挂载、stacking context和overflow裁切，再覆盖组件Token。禁止任意极大值或全局改popup容器来掩盖单个问题。

### 3.4 主题与样式

#### 3.4.1 语义变量

色彩和排版使用附录A.2，布局与项目尺寸使用A.3。静态CSS适用于默认亮色；动态主题使用与配置一致的Token或CSS变量，不保留两套独立主题值。

#### 3.4.2 组件与主题配置

- 使用`ConfigProvider.theme`配置token、algorithm和components；组件属性匹配项目安装版本。
- Button按用途使用primary/default/text/link，危险操作使用danger；输入错误使用对应status。
- 单行控件尺寸使用small/medium/large，默认medium；多行文本使用Input.TextArea，日期区间使用DatePicker.RangePicker。
- Modal/Drawer使用open控制，必要样式通过styles/classNames限定范围；Modal遮罩关闭使用mask.closable，Drawer尺寸使用size。
- 表格查询、排序、分页和选择采用明确的受控状态，使用稳定rowKey。
- 动态主题使用defaultAlgorithm、darkAlgorithm或compactAlgorithm；暗色不手工反色。message、modal和notification使用当前主题上下文。

#### 3.4.3 主题与组件样式一致性

- 同值不同语义使用独立Token；主题变化时同步文字、背景、边界、图标、浮层与图表。
- 定制优先使用主题或组件Token，其次使用组件语义样式；局部CSS限定到相应组件和变体，不依赖全局哈希类。
- 高亮、禁用、错误、加载、长文本和不同密度下保持视觉角色一致；文字、焦点与边界可辨认。

### 3.5 禁止硬编码清单

| 问题 | 执行方式 |
| --- | --- |
| 页面散落品牌/状态真值 | 消费已批准语义Token；主题定义集中维护 |
| 全部表面统一白色别名 | 页底、容器、浮层及表头分别绑定 |
| 全组件统一6px圆角 | 控件6、表面8、小Tag4按角色和实际组件处理 |
| 固定使用与任务不匹配的输入样式或表格密度 | 使用Ant Design目标变体及Token |
| 用官网YAML名直接写theme.token | 映射到实际SDK Token名，见3.2.1 |
| 擅自造色/任意曲线 | 使用功能/预设色及官方动效Token |
| 整块opacity表示禁用 | 使用disabled及组件派生样式 |
| 极大z-index或transition:all | 排查上下文；只过渡必要属性 |
| 暗色仅改页底 | 同步文字、控件、浮层与图表的主题 |

Token定义、主题配置与用途覆盖可包含设计值；0、100%、布局比例和内容驱动值不机械Token化。源组件11px/15px等几何保留依据，项目12px选择器覆盖按5.3.3明确执行。

## 第 4 章 布局与页面架构

> 本章定义"页面的骨架"。组件怎么选见第 5 章，容器内交互见第 6/7 章。

### 4.1 应用框架

#### 4.1.1 两种框架与选择依据

| 框架 | 结构 | 选择依据 |
| --- | --- | --- |
| A侧边导航式（默认） | 全宽顶栏 + 左侧导航 + 右侧内容 | 模块较多、存在层级、经常切换任务 |
| B顶部导航式 | 顶部主导航 + 下方内容 | 模块少且扁平，不压缩主要内容 |

后台项目默认A；明确采用其他已批准模板时保持该模板。一级模块数量作为参考，不能仅按4/5个硬切。

#### 4.1.2 框架 A 尺寸规格

采用Ant Design Layout组合。

```text
┌────────────────── 顶栏64px ────────────────────┐
├─────200/80px─────┬──────────────────────────────┤
│ 侧边导航         │ 面包屑 / 标题 / 主要操作      │
│                 │ 内容区                       │
│                 │ 列表 / 表单 / 详情 / 工作台   │
└─────────────────┴──────────────────────────────┘
```

| 区域 | 默认值 |
| --- | --- |
| 顶栏 | 64px，对应Layout.headerHeight默认 |
| 侧栏展开/折叠 | 200/80px，对应Sider width/collapsedWidth默认 |
| 框架配色 | 亮色Header/Sider，内容用colorBgContainer；需显式配置，非SDK默认深色导航 |
| 内容边距 | ≥1200px取24px；1024—1199px取16px；更窄见4.3 |
| 标题 | 20/28、600 |
| 标题与首区块 | 12px，按3.3.8.1 |
| 同级内容模块间隙 | 水平/垂直12px；分类面板与列表、Card与Card共用该值 |
| 内容Card | 圆角8px、默认body24px；嵌套表格时避免重复内距 |

- 导航层级优先简单；超过3级先评估搜索/分组和信息架构。
- 侧栏内容长时可独立滚动，sticky区不遮挡焦点；折叠后保留名称、图标和子菜单入口。
- 有路径上下文时提供面包屑；用户区在顶栏右侧。Header内部padding按项目布局配置，不把SDK默认50px水平内距无条件套入所有框架。

#### 4.1.3 页面标题区

```
页面标题                                    [次操作] [主操作]
页面说明（一句话，可选，colorTextTertiary 14px）
```

- 标题用具体名词："订单列表""客户详情"，**禁止**"信息管理"这类空泛词
- 操作区在**右上角**，主操作在最右
- 无操作时标题区只占标题一行，不要留空的操作区占位

#### 4.2.1 列表页

| 区块 | 规则 |
|---|---|

| 筛选按钮 | 页级已有主要动作时，筛选查询使用default按钮；全屏常态仅一个主要强调，分区主操作按5.2.1配置 |
| 批量操作条 | 选中 ≥1 项时在**表格上方**出现（不是页面底部） |
| 表格 | 见5.5.1；优先展示任务核心列，数据较多时可用列设置和横滚，不按8列硬截 |
| 操作列 | 最多 2 个文字按钮，超出收进"更多" |
| 分页 | 右下角，与表格间距12px，按3.3.8.1 |

筛选与表格可位于同一容器或按任务分区，避免重复边框和重复内距。指标、图表和独立业务模块仅在服务主任务时提供。

| 区块 | 规则 |
|---|---|
| 返回 | 左上角，带返回图标 |

| 操作 | 右上角，主操作 1 个 + 次操作 ≤2 |
| 连续查看 | 按调用视图的对象顺序与权限范围切换；条件或数据变化时校正位置，关闭后返回原对象入口 |

- 图标 + 标题 + 说明 + **最多 2 个操作**
- 用于流程终态（提交成功、支付完成、无权限、404）
- 无权限场景：说明范围并按7.6.2提供真实可用的申请/联系路径或返回，不将权限不足误标为系统错误

---

### 4.3 响应式与断点

Grid官方断点与项目支持范围分别定义；1440px为设计基准，完整桌面任务目标≥1024px。

| 视口宽度 | 项目布局行为 |
| --- | --- |
| ≥1600px（xxl） | 阅读内容最大1440px居中；数据工作区可流式；表单不无意义拉长 |
| 1200—1599px（xl） | 标准桌面、内容边距24px；筛选按最小宽折行 |
| 1024—1199px（lg内项目区间） | 边距16px、导航默认折叠80px；Card/Descriptions按空间减少列数 |
| 992—1023px（lg内受限区间） | 受限桌面模式，导航可展开；表格横滚，复杂编辑优先独立页 |
| 768—991px（md） | 导航以可展开面板呈现；主内容保留，表格横滚，必要操作可达 |
| 576—767px（sm） | 不承诺完整桌面编辑；单列、16px边距，保留阅读/返回及必要操作路径 |
| <576px（xs） | 极窄支持按任务声明；不静默删除必要字段，不制造无出口提示 |

1024px是项目任务支持阈值，不能冒充Ant Design的lg断点。卡片按minmax/内容宽度计算列数；表格可用列设置/横滚，必要字段始终有访问路径。Modal四周默认24px，<768px可16px；文字缩放、焦点、长文案、固定操作区和滚动均按目标视口验证。

### 4.4 页面密度

管理列表优先`Table size="medium"`；同表格密度统一。Table的size与表单控件尺寸分别配置，不能把32px控件高度当作表格行高。

| Table size（6.6.8） | cell上下/左右padding | 文字 | 单行基础高度估算 |
| --- | --- | --- | --- |
| large（SDK表格默认） | 16/16px | 14/22 | 约55px，含1px下边界 |
| medium（项目列表默认） | 12/8px | 14/22 | 约47px，含1px下边界 |
| small | 8/8px | 14/22 | 约39px，含1px下边界 |

表中行高为基础估算；多行文本、Tag、Avatar、按钮和图标可增加实际高度，不设置固定高度裁切内容。

控件small/medium/large通常为24/32/40px；密度切换不把所有文字同时缩到12px。变更需保留筛选、排序和稳定ID选择状态，并重算固定列与阴影。

### 4.5 滚动与吸底

优先一个明确的主要纵向滚动区域，避免同方向嵌套争抢；侧边导航、表格横向滚动和弹窗局部滚动并非一律禁止。

| 场景 | 策略 |
| --- | --- |
| 内容型/详情页 | 页面内容纵向滚动，必要页签可吸顶 |
| 高密度表格工作区 | 可固定内容区域让表体滚动；表头与固定列背景不透明 |
| 长表单 | 按实际高度选择内容滚动与吸底操作，避免遮住字段/错误 |
| Modal/Drawer | 保持标题与操作可达，内容超过可用高度时滚动 |

吸底条高度、边距和层级按所选模板；焦点滚动应避开吸顶/吸底遮挡。不能用“超过20行/20字段”作为是否独立滚动的唯一判据。

## 第 5 章 组件规范

> 单个组件的完整条目模板：**用途 → 结构解剖 → 尺寸档位 → 状态 → 文案 → Do & Don't**。
> 交互"什么时候用"见第 6 章，表格数据规范见第 8 章，表单字段规范见第 7 章——本章只写**组件自身的规格**。

### 5.1 组件通用约定

#### 5.1.1 命名与变体范式

按各组件真实API建模，不要求所有组件拥有同一组变体：

| 组件 | 常用建模维度 |
| --- | --- |
| Button | type或color/variant、danger、shape、size、loading、disabled、icon |
| Input/Select | variant、size、status、disabled、前后缀/选项；输入与选择行为分别处理 |
| Card | size、variant、title/extra、cover、actions、loading |
| Table | size、bordered、columns、rowSelection、pagination、scroll和受控状态 |
| Tabs | line/card/editable-card等合法类型、items、activeKey、disabled |

组件组合只包含任务所需结构与适用状态，避免无意义的变体组合。

#### 5.1.2 尺寸档位（全站统一）

常见单行Button/Input/Select采用以下三档：

| 用途 | size | 高度 |
| --- | --- | --- |
| 小尺寸紧凑区 | small | 24px |
| 默认控件 | medium | 32px |
| 大尺寸强调或较宽松输入 | large | 40px |

没有通用mini尺寸。兼容middle已弃用，新代码用medium；Drawer/Card/Table等另查自己的size含义。默认Button为6px圆角，design.md标准按钮水平padding15px、Input为4px11px，不能将其外推给icon-only和多选等变体。同一操作组保持基线和高度协调。

#### 5.1.3 状态必须齐全清单

按组件语义定义适用状态；不是所有组件都需要error或loading。

| 状态 | 规则 |
| --- | --- |
| 默认/悬停/按下 | 复用目标组件；主要按钮#1677FF→#4096FF→#0958D9 |
| 聚焦 | 键盘焦点清楚；不移除唯一outline，复合控件入口可识别 |
| 选中/展开 | 与按下状态不同，提供对应语义属性 |
| 禁用 | disabled与视觉/触发一致；原因通过附近文字或独立可达帮助提供 |
| 加载 | 防重、保持尺寸；实际请求范围明确，不伪造百分比 |
| 校验错误/警告 | 字段与表单级分别表达，不只靠红/黄边框 |

Outlined/filled等变体分别使用自己的状态，不能拿一个统一背景覆盖全部控件。各状态保持焦点可见、键盘可操作和足够对比。

#### 5.1.4 组件扩展

- 优先组合现有组件；组件覆盖不了任务时才定义专用结构。
- 自定义组件具备5.1.3所列适用状态、可访问名称和键盘操作。
- 两个及以上真实页面共用的结构可作为通用组件，单页面特有结构限定在页面内。

#### 5.1.5 业务状态与颜色

业务状态明确名称、条件、允许操作和视觉语义。

| 定义项 | 内容 |
| --- | --- |
| 状态标识与名称 | 稳定值、界面名称及必要解释；同义状态全站一致 |
| 成立与退出条件 | 何时进入、何时结束、由谁/什么事件更新 |
| 可执行操作 | 允许的动作、条件、成功后的状态；权限按7.6.2判断 |
| 视觉表达 | 语义Token、文字/图标、适合的Tag/Badge/Alert；不能仅靠颜色 |
| 数据边界 | 与其他状态能否同时存在，缺失/未知时如何展示 |

**通用语义默认**：

| 含义 | 默认颜色用途 | 适用说明 |
| --- | --- | --- |
| 未开始、草稿、待分配 | 中性色 | 状态尚未进入处理流程 |
| 正在处理 | colorPrimary及colorPrimaryBg | 表达流程进行中，不代表完成 |
| 任务成功完成 | colorSuccess及colorSuccessBg | 需有真实完成结果；归档/停用不自动等同成功 |
| 临期、需要关注 | colorWarning及colorWarningBg | 尚未超过已约定截止时间的提醒 |
| 已逾期、失败、错误风险 | colorError及colorErrorBg | 逾期依据业务截止时间和时区判断；不将正常业务分类误标为错误 |
| 暂缓、关闭、归档 | 通常使用中性色 | 存在独立风险时另行表达风险 |

分类色与风险色分别定义，业务状态、优先级和逾期风险可同时存在，分别表达。

任务逾期使用colorError，临期使用colorWarning；明确的业务含义调整按0.3确定适用范围。状态成立条件与日期精度见10.5.2，统计涉及的状态集合见8.7.3。

### 5.2 操作类组件

#### 5.2.1 按钮层级

| 目的 | Ant Design实现与默认表现 |
| --- | --- |
| 当前页面主要动作 | type="primary"，默认蓝底白字；32px高、6px圆角 |
| 次要动作 | type="default"，默认白表面、描边与正常文字 |
| 文本/链接动作 | type="text" / "link"，按上下文区分操作与导航 |
| 添加类弱入口 | 需要时type="dashed" |
| 危险动作 | danger与合适type配合；确认需说明对象/后果 |
| 纯图标动作 | 使用icon与可访问名称，形状按任务选择 |

常态页面默认一个主要强调。筛选查询通常用default，页级新建承担primary；Modal打开时当前任务使用primary，背景不可操作。任务明确、互不竞争的分区确需多个主要动作时，按0.3明确适用范围，不能自动把每个按钮组都视为例外。

优先明确动词；语境清楚时允许“确定/完成”。加载防重复请求并维持可读名称；危险和禁用是不同语义，不以透明度替代disabled。color/variant与type/danger的优先关系按目标版本，避免冲突混写。

#### 5.2.2 Button-group 按钮组

Button-group用于组合相关动作，其本身不意味着互斥选择。互斥视图切换应使用合适的Radio按钮组/分段选择等，选择状态与执行动作区分。根据选项长度和可用空间决定是否改Select，不强制所有组≤4项。

#### 5.2.3 通用辅助件

| 组件 | 位置 | 规则 |
|---|---|---|
| 查看更多 | 卡片底部或列表末尾 | 整块可点，不要只让文字可点 |
| 查看全部 | 区块标题右侧 | 与标题基线对齐 |
| 换一批 | 推荐类卡片右上角 | 文案固定为"换一批"，配刷新图标 |
| 更多分类 | 分类导航末尾 | 展开后收起文案变为"收起" |

**规则**：这些辅助件在同一页面内**文案必须完全一致**，禁止"查看更多"和"更多"混用。

### 5.3 输入类组件

#### 5.3.1 控件选择对照表

按数据关系、同时比较的必要性、可定位性和可用空间选择控件。

| 数据与任务特征 | 优先控件及判断 |
| --- | --- |
| 单选，选项短且需要一眼比较，空间足够 | Radio / 合适的互斥按钮组，保持选项可见 |
| 单选，需收纳选项或版面紧凑 | Select；短而稳定的选项可不带搜索 |
| 选项较长、较多，或用户会按名称定位 | 支持搜索的Select；远程数据说明加载、无结果与错误 |
| 有层级关系（省市区、组织架构） | 按路径选择用Cascader，按树节点选择用TreeSelect |
| 是/否，且立即生效 | Switch，说明写入与失败恢复 |
| 是/否，随表单一起提交 | Checkbox或合适的表单选项 |
| 多选，选项能清楚直接排列 | Checkbox组 |
| 多选，需收纳或搜索定位 | Select多选，已选内容可查看/移除；API按目标工程类型 |
| 数值 | InputNumber；单位通过标签或已支持的前后缀表达 |
| 单个日期 / 日期区间 | DatePicker / RangePicker，明确日期或时刻及边界 |
| 单行文本 / 多行文本 | Input / Textarea；长度规则由业务字段定义 |
| 富文本 | Editor，按真实编辑任务另行评估 |

“2~5项”“超过5项”等仅可作为初筛示例，不作为自动切换控件或强制搜索的阈值。3项使用Select可以符合紧凑布局；需要同时比较却反复打开下拉、或长列表没有有效定位能力时，应重新选择控件。

**检查**：默认值、清除语义、选项禁用原因、长标签、空选项、键盘选择及结果提交时机均明确。Select布局留白按5.3.3。

#### 5.3.2 通用规格

常见默认Input/Select为outlined，白表面、1px边界、6px圆角；small/medium/large通常为24/32/40px。默认Input padding4px11px，聚焦使用组件主色边界与焦点效果，不额外强制增加实线边框厚度而造成跳动。

- 多行使用Input.TextArea；多选、数字、日期和上传按实际组件结构处理，不继承单行高度。
- filled/borderless/underlined是合法变体，项目默认outlined，其他变体按用途选择。
- 清除按业务选择；清除值、空字符串、未选择和0的含义不能混用。
- 标签可见或有等效名称，placeholder只提供示例。搜索能力按5.3.1，宽度按任务与容器。
- 选择器保留项目12px等边距覆盖，实际测量文字起点和箭头盒，见5.3.3；不把SDK11px padding直接当已经满足覆盖。

#### 5.3.3 选择器箭头与左右留白

中尺寸（32px高）Select及同类单行下拉触发器，左侧文字起点到容器内边界为12px，右侧箭头图标盒到容器内边界也为12px；箭头图标盒12×12px并垂直居中，文字与箭头至少间隔8px。

- 覆盖筛选栏、编辑弹窗、组卷表单和分页条数选择器；相同尺寸控件保持一致，不因容器变窄而把箭头挤到边框。
- 自定义单行选择器默认左内距12px、右侧文字预留32px（12px外侧留白＋12px图标盒＋8px间隔）；长文本在内容区域省略，不进入箭头区域。
- 原生HTML `select` 不依赖浏览器默认箭头的位置。可在页面组件样式内使用 `appearance:none` 配合固定位置图标，保留原生选择、键盘和可访问语义；多选/列表框不套此箭头规则。
- 箭头不应挡住点击，也不单独进入Tab顺序；hover、focus、错误和禁用状态均应保留箭头和留白。清除、加载等附加图标依组件结构另行预留空间，不与箭头重叠。
- 使用实际Ant Design组件时优先采用组件属性、主题或受控样式覆盖；不全局改写源组件内部节点。不同尺寸或品牌样式需明确适用范围。

### 5.4 导航类组件

| 组件 | 默认规则与边界 |
| --- | --- |
| Tabs | 默认line：活动主色文字+2px下划线，非活动文字按实际组件Token；card/editable-card合法，不能将“line无底色”外推全部类型 |
| Menu | 亮色选中态使用浅蓝#E6F4FF与主色文字；不叠加额外指示条。Menu与Layout配色一致 |
| Breadcrumb | 组织路径上下文，长路径可折叠但保留有效返回层级 |
| Pagination | 每页10条为项目默认；受控current/pageSize与列表状态联动；条数选择器也遵守5.3.3 |
| Steps | 表达阶段依赖，进度与数据保留清楚；复杂可回访任务用独立页 |
| Anchor | 长内容导航，跳转位置避开sticky遮挡 |

Tab与面板建立语义关联，处理方向键、焦点及选中状态；当前Menu路径不能只凭颜色。导航入口与执行动作区分，链接可按任务提供复制/打开新页。

### 5.5 数据展示类组件

#### 5.5.1 Table（组件侧规格）

- 默认组件size为large，项目管理列表默认medium，padding与估算高度见4.4。14/22文字，表头600；默认headerBg=#FAFAFA，边界colorBorderSecondary。
- 默认没有斑马纹；hover、选中、固定列和排序列分别复用组件状态。斑马纹仅在提高可读性时使用。
- 使用稳定rowKey、明确列宽、必要的scroll和固定策略；不以同一个padding全局覆盖全部表格。
- 行含多行文字、头像或控件时可增高；不从截图或基础估算推导所有tr固定高度。
- 固定列阴影遵守8.1.4，新增列、缩放、密度、分页、resize后均按实际滚动元素重新判断。

#### 5.5.2 其他展示组件

| 组件 | 设计及使用边界 |
| --- | --- |
| Tag | design.md范式12/20、4px圆角、水平padding7px；用于分类和非关键标签，实际variant/边框按组件 |
| Badge | 状态点/计数按各自模型；关键状态带明确文字，点不能代替可达说明 |
| Avatar | 使用真实size/shape与缺省策略，不把圆形头像强改通用半径 |
| Descriptions | 标签/值分层，列数按空间；只读资料可复制，必要内容不藏入disabled控件 |
| Tree/TreeSelect | 树导航与字段选择分别处理，节点含义、展开及选择状态清楚 |
| Collapse | 依内容优先级设置展开；错误和必填内容不能默认藏到无提示区域 |
| Timeline | 顺序、时间与状态清楚，长记录按任务分页/加载/折叠 |

关键异常、危险状态或需立即处理的信息用Alert或带文字的Badge/状态区，不只用一枚淡色Tag。详情标题可附一般状态Tag，同时说明关键风险。

#### 5.5.3 Tooltip 与 Popover 的边界

| 维度 | Tooltip | Popover |
|---|---|---|
| 内容 | **纯文字**，≤20 字 | 可含标题、链接、表单、操作 |
| 交互 | 不可操作 | 可点击、可交互 |
| 触发 | hover / focus | click |
| 消失 | 移开即消失 | 点击外部或关闭按钮 |

**判定规则**：
- 需要用户**点进去做什么** → Popover
- 只是**解释一下这是什么** → Tooltip
- **禁止**：在 Tooltip 里放链接（鼠标移动过去就消失，点不到）
- Popover内容短也可以用于点击触发的可达说明；Tooltip/Popover主要按交互和触发需求区分，不按句数判断
- **禁止**：用 Tooltip 装载必要信息（键盘用户和触屏用户触达不到），必要信息应放页内可见的说明文本

### 5.6 反馈类组件

| 组件 | 用途与边界 |
| --- | --- |
| message | 短暂即时反馈；时长按信息长度，不用短暂消息承载唯一撤销机会 |
| notification | 异步/后台结果，必要时可持续和可操作；通过App或hook接入主题上下文 |
| Alert | 持续状态与表单级问题；浅功能底+正常正文+状态图标，关闭按重要性决定 |
| Modal | 默认width520px，表面8px圆角、遮罩rgba(0,0,0,.45)；项目表单宽档/焦点/滚动见6.2/6.4 |
| Drawer | 6.6.8预设size default378px、large736px，支持自定义；项目宽档另列，不把预设强当所有面板 |
| Spin/Skeleton | 根据请求粒度与已有内容选择，避免局部请求替换整页 |

## 第 6 章 交互模式与场景决策

> 本章回答"这个交互该长什么样"。所有条目都是**可判定**的，遇到边界情形按 6.1 的判定顺序走，不要凭感觉选。

### 6.1 容器决策树

先判断任务状态与复杂度，再评估上下文和空间。以下为项目默认，不是Ant Design字段数量限制。

```text
需要可回访链接、草稿、多阶段状态、长时间编辑或复杂关联？
  是 → 优先独立页/分步页；保留上下文可用分区或参照面板
  否 → 列表中单个对象的基础信息编辑，且能在一个任务内完成？
         是 → 默认Modal；保留列表筛选、页码、选择与滚动位置
         否 → 需要持续对照列表、连续切换处理对象？
                是 → 评估Drawer；明确遮罩与焦点是否阻断主页面交互
                否 → 单一短任务用Modal；局部微操作可行内/Popover
需要同时操作主页面时 → 行内/并排区域，或经验证可交互的非模态面板
内容是否在目标屏宽/文字缩放下仍清楚、操作可达？
  否 → 扩展布局或改独立页，避免无限加宽弹窗
风险与可逆性在每个阶段评估 → 明确对象、后果和保护动作
```

字段数只作初筛，不能先按“需要上下文→Drawer”直接返回而跳过草稿/分享需求。Drawer可见主页面不代表主页面仍可交互。

### 6.2 容器决策矩阵

| 场景 | 优先容器 | 关键判断 |
| --- | --- | --- |
| 单对象局部微编辑 | 行内/Popover | 聚焦、可达、可恢复 |
| 闭合单步短任务 | Modal | 输入、校验与操作完整可达 |
| 列表单对象基础信息编辑 | **Modal** | 保留列表上下文，一个任务内保存 |
| 持续对照列表、连续切换对象 | Drawer | 参照/连续处理有实际价值；遮罩和焦点策略明确 |
| 多分组、复杂校验、大编辑表格 | 独立页或足够空间的Drawer | 容量、回访和状态管理 |
| 分享/打印/草稿/复杂分步 | 优先独立页 | 独立路由与恢复 |
| 非阻断结果 | message/Alert/notification | 时长与操作需求 |

**Modal项目宽档**：S400、M520、L720、XL960，按内容选择；默认M520，列表较宽双列表单可用L720。只有普通Modal的520px对应SDK默认，项目S400不等于Modal.confirm默认416px。表面圆角8px。

**Drawer项目宽档**：S378、M480、L736、XL960。378/736对应6.6.8预设default/large；480/960是自定义size项目候选。宽度适合内容与视口，超出容量改用独立页。

四周默认24px，窄屏16px；内容过高时只让实际内容区滚动，标题和页脚可达。加宽不能替代任务拆分与状态设计。

### 6.3 表单样式选用规则

#### 6.3.1 单列 vs 双列

| 条件 | 布局 |
|---|---|
| 一般连续填写任务 | 优先单列，按内容长度与空间决定 |
| 字段短、关联清楚且空间足够 | 可双列，不以字段数自动触发 |
| 字段需纵向比对填写（如"期初/期末""计划/实际"） | 双列，成对字段并排 |
| 含富文本 / 表格 / 上传预览 | 单列，控件占满宽度 |

**理由**：单列便于连续填写；双列适合短字段、成对比较与合理空间利用。选择取决于任务关系而非仅字段总数。

#### 6.3.2 标签位置

| 条件 | 标签位置 |
|---|---|
| **默认** | 标签在上，控件在下（间距 `--ui-space-12` 12px） |
| 字段短且需横向紧凑（数字、日期、开关） | 标签在左，右对齐，宽 80px |
| 双列布局 | 标签在左（垂直空间紧张） |

**规则**：同一张表单内**标签位置必须统一**，禁止混用。

#### 6.3.3 分组 / 折叠 / 分步

| 条件 | 策略 |
|---|---|
| 任务简单、关系连续 | 可不分组 |
| 存在自然信息组 | 按语义分组，不强制组数 |
| 阶段之间有依赖且可逐步完成 | 分步，明确进度与数据保留 |
| 分组后有"次要/高级"内容 | 折叠（默认收起） |

复杂、可回访分步优先独立页面；轻量局部流程可评估Modal/Drawer承载，但应提供进度、返回和数据保留。浏览器返回行为由路由实现决定。

#### 6.3.4 何时用行内编辑表格代替表单

同构多行、需要同时比较/批量填写时考虑可编辑表格。每行字段少且内容短时通常更容易管理；每行字段与总行数仅作可读性参考，不是组件能力上限。

需要明确行级/单元格校验、保存范围、批量失败恢复与键盘流。复杂对象可进入详情编辑，不能因超出某个字段数就强制逐条弹窗。

#### 6.3.5 表单操作区

- 独立页操作组左对齐，组内次操作在左、主要动作在右，与7.4.1一致
- 弹窗/抽屉内：操作区固定在底部，右对齐；内容区独立滚动
- 独立页面表单：操作区跟随内容底部，或吸底（`--ui-z-sticky`）
- 按钮文案优先具体动词；语境明确的确认允许“确定”，避免无法判断后果的泛用词

### 6.4 弹窗样式选用规则

#### 6.4.1 四种类型与用途

| 类型 | 用途 | 是否含表单 |
|---|---|---|
| 确认框 Confirm | 是/否决策，无输入 | 否 |
| 信息弹窗 Dialog | 展示一段需立即处理的信息 | 否 |
| 表单用途的Modal | 收集一个闭合任务的输入 | 按实际容量评估，不设通用字段上限 |
| 抽屉 Drawer | 需持续对照列表、连续处理对象，或内容超过Modal合理容量 | 可 |

#### 6.4.2 结构

```
┌─────────────────────────────┐
│ 标题 (h2 16/24)          [×] │   ← 必须有标题，禁止无标题弹窗
│ 描述文字 (base 14/22)        │   ← 可选，一句话说明后果
├─────────────────────────────┤
│                             │
│  内容区（可滚动）            │   ← 超过容器高度时此区滚动
│                             │
├─────────────────────────────┤
│              [取消] [确定]   │   ← 固定底部，不随内容滚动
└─────────────────────────────┘
```

- 标题：动词短语，如"删除部门"，**禁止**"提示""系统消息"
- 描述：说明后果，不重复标题
- 内容区按扣除标题、页脚和边距后的实际高度滚动，标题与底部操作保持可达。
- 底部操作区：始终固定，带顶部 1px `--ui-color-border` 分割

#### 6.4.3 按钮顺序与默认焦点

- 顺序：**次操作在左，主操作在右**
- 初始焦点按任务选择标题说明、首个字段或合适操作；表单不默认把焦点放在提交按钮。关闭后归还触发元素
- **例外**：危险操作（删除/停用）默认聚焦**取消**，避免连击回车误删
- 危险操作按钮用 `danger` 样式，文案用具体后果："删除 3 项"，而非"确定"

#### 6.4.4 关闭规则

| 触发 | 确认任务 | 编辑任务 | 只读查看 |
| --- | --- | --- | --- |
| 关闭按钮 | 可用 | 可用，处理未保存修改 | 可用 |
| Esc | 取消/关闭 | 先关闭当前子浮层，再按未保存状态处理 | 关闭 |
| 遮罩点击 | 默认不执行确认动作 | 默认不直接关闭，避免误触丢输入 | 可关闭 |
| 浏览器返回 | 按路由 | 路由驱动任务返回前保护未保存值 | 路由驱动面板可返回关闭 |

未保存内容不得静默丢失；可选择继续编辑、丢弃或保存草稿。提交中是否允许关闭/转后台取决于取消机制和任务持久化，状态必须可查询。关闭后归还触发元素或合理的后继焦点。

#### 6.4.5 嵌套与叠层

默认仅一个任务型Modal/Drawer；必要的丢弃修改确认可以成为短暂第二层，完成后焦点归还原容器。选择器/日期/Tooltip等归属当前任务，不按第二个表单容器计数。多个任务容器反复嵌套时重新评估流程；层数本身不能替代焦点、遮罩和状态管理。

#### 6.4.6 弹窗内表单硬约束

- 内容、错误和操作在目标视口可达，超过可用高度时只有内容区域滚动。
- 弹窗采用纵向伸缩布局，标题和页脚不收缩；实际body及外层包装允许收缩，body设置min-height:0和overflow:auto，不能只给外框设置max-height。
- 复杂分组、编辑表格、富文本或长步骤优先评估独立页，而非仅统计字段/行数。
- 校验失败保持输入，字段错误就近；服务级错误在表单级表达，不能把所有失败强行塞到某字段。
- 成功后关闭/跳转/保留结果按任务定义，刷新原视图时保留必要筛选与位置。
- 对象关联短任务先展示对象摘要，只提供必要字段；新增记录不自动推导业务流程完成，提交作者与时间使用可信上下文。

#### 6.4.7 窄屏降级

按4.3实际支持策略决定适配。可用宽度不足时调整Modal尺寸、改全屏面板或独立页，保持任务状态和返回路径；内容超过视口70%可先内容滚动，不机械改成Drawer。

#### 6.4.8 列表“编辑”默认交互

**默认规则**：列表行内“编辑”打开居中的表单Modal，用于修改当前对象的基础信息。列表保留在背景中，编辑不触发页面跳转。

| 项目 | 执行规则 |
| --- | --- |
| 标题与对象 | 标题使用“编辑 + 对象”，例如“编辑课件”；正文回填当前记录，必要时显示编号或文件摘要 |
| 尺寸 | 常规单列表单可用M520；需要文件摘要、合理双列等内容时可用L720。按内容与目标视口选择，沿用6.2宽档，不按字段数强制切换 |
| 内容与操作 | 标题、关闭入口和底部操作保持可达；仅内容区滚动。底部右对齐排列“取消”“保存修改” |
| 校验与防重 | 按7.3在字段附近反馈错误，聚焦首个错误并保留输入；提交期间阻止重复保存 |
| 关闭与未保存保护 | 遮罩默认不直接关闭；取消、关闭按钮和Esc先处理当前子浮层，再检查未保存内容，提供“继续编辑”“放弃修改” |
| 保存与列表恢复 | 成功后关闭弹窗，更新记录；按8.2.4保留筛选、页码、每页条数、有效选择与滚动位置。记录离开当前结果或总页数减少时按该表校正，反馈变化原因 |
| 焦点 | 打开时进入首个适用字段；焦点限制在当前弹窗；关闭后返回触发的“编辑”，记录已离开当前结果时进入列表标题或其他合理后继位置 |
| 窄屏 | 依6.4.7收窄并在必要时改为单列，保持标题、保存和取消可达，不静默删除字段 |

**例外**：明确的单元格微操作可保持行内/Popover；持续对照列表或连续处理对象可采用Drawer；需要可回访链接、草稿、复杂关联或分步流程时采用独立页。容器按任务复杂度选择，不能仅因“需要保留上下文”自动把所有列表编辑改为Drawer。

### 6.5 反馈方式选择规则

| 反馈类型 | 用时 | 是否阻断 | 位置 |
|---|---|---|---|
| 内联错误 | 字段校验 | 否（阻断提交） | 字段正下方 |
| Message 轻提示 | 操作即时反馈 | 否 | 使用工程反馈区，时长按信息长度与操作需求 |
| Alert 页内条 | 需持续可见的状态说明 | 否 | 页面/区块顶部，可关闭 |
| Notification 通知 | 后台完成、持续或系统消息 | 否 | 通常右上，重要/可操作消息允许持续至关闭 |
| Modal | 必须用户决策 | 是 | 居中 |
| Result 结果页 | 流程终态 | — | 独立页面 |

**选择规则**：

1. **错误一律就近**：字段错误显示在字段下方，表格行操作失败显示在该行，**禁止**统一用 Message 报字段错误
2. **成功提示能省则省**：如果结果在界面上肉眼可见（比如列表里多了一行、开关已变状态），**不需要** Message
3. **需要 Message 的情况**：结果不在当前视野内（如"已导出，请到下载中心查看"）、或操作有延迟
4. **Alert 用于持续性状态**：如"该数据源近 7 天未同步"，不是一次性事件
5. Notification适合持续或异步结果，包括用户主动触发的后台任务；按可操作性和持续时间选择，不按事件发起者划绝对边界

### 6.6 危险操作与可逆性设计

按风险分四级，**先问能不能撤销，再决定要不要确认**：

| 级别 | 特征 | 交互 | 示例 |
|---|---|---|---|
| L1 可撤销 | 有明确逆操作 | 直接执行 + Message 内"撤销" | 归档、置顶、标记已读 |
| L2 轻损失 | 删除但可恢复 | 一次确认（Confirm） | 删除单条记录 |
| L3 重损失 | 删除且难恢复 / 影响他人 | 确认 + **输入名称/数量验证** | 删除部门、批量停用账号 |
| L4 不可逆 | 涉资金/权限/生产数据 | Confirm + 输入验证 + 结果通知；或改走审批流 | 注销账号、清空数据库 |

**规则**：
- 对低影响且可靠可撤销的L1操作优先直接执行；涉及外部影响或撤销无法消除的后果时仍评估风险
- 提供撤销时窗口应足够操作，默认给予至少10s可操作时间；与默认短Message时长区分，可用持久结果区或回收站继续恢复
- 高影响操作如需输入确认，可核对对象名、数量或特定短语；选择应帮助理解后果，不能代替权限/审批与服务端约束
- 危险操作按钮**不默认聚焦**（见 6.4.3）
- 批量删除的确认文案必须带**数量**："删除选中的 12 项"，禁止"确定删除吗？"

### 6.7 批量操作与选择模式

- 使用批量操作时，行首复选框常驻，选中后在表格上方展示操作条。
- 默认范围为**当前页**，表头复选框名称为“选择当前页全部项”。翻页、排序、切换分组等按8.2.4处理选中项。
- 只有真实支持跨页批量时，才提供独立的“选择当前筛选结果全部N项”入口，区分当前页全选与全结果选择；提供取消范围选择的方式。不能显示入口却只提交当前页ID。
- 操作条表达`已选N项（范围）`与可执行动作；超过3个动作可收进更多。确认/提交使用当时已说明的对象集合，服务端再次校验权限、状态和结果集合版本。
- 成功、失败和结果未知分别反馈。全部成功后清除已处理选择；部分失败保留仍可见的失败项选择并给逐项原因，超时未知按9.4查询状态后再决定后续动作。
- 少量失败可就地列出；较多失败或异步任务可提供有权限控制的错误明细下载。重试仅针对已确认可重试的失败项。

批量作用范围、操作后页码/滚动及导出范围统一见8.2.4；不因勾选图标的样式推断选择范围。

### 6.8 异步与长任务

| 预估时长 | 交互 |
|---|---|
| <1s | 按钮 loading，无其他提示 |
| 1~10s | 按钮/相关区块loading与防重；不因一次提交覆盖整页为Skeleton |
| 10s~2min | 进度条，允许在页面内操作其他内容 |
| >2min | 转后台任务 + Notification 通知结果，**允许离开页面** |

**规则**：
- 提交后**立即禁用按钮**并进入 loading，防重复提交是底线
- >2min 的任务必须提供任务中心/结果页入口，不能让用户干等
- 部分失败必须说明哪部分成功、哪部分失败，**禁止**笼统报"操作失败"
- 后台任务只有服务端已持久化才可承诺离页继续；路由切换停止无用轮询，任务中心可恢复查询

### 6.9 常见反例库

评审时区分事实错误、交互缺陷与有理由的项目默认偏离。

| # | 反例 | 修正方向 |
| --- | --- | --- |
| 1 | 多分组、编辑表格和复杂校验挤进小Modal | 按6.1评估独立页/合适Drawer；不是仅按字段数选720px |
| 2 | 长流程无进度、不能回退、步骤切换丢数据 | 明确流程状态与恢复策略，复杂任务优先独立页 |
| 3 | 连续嵌套多个任务容器导致焦点混乱 | 一个主任务容器，必要确认后归还原焦点 |
| 4 | 遮罩/关闭直接丢弃未保存输入 | 关闭前保留或确认，避免静默丢数据 |
| 5 | 危险操作被默认Enter意外触发 | 危险按钮不被意外初始聚焦，说明后果 |
| 6 | 删除只写“确定删除吗” | 标明对象、数量、影响与恢复条件 |
| 7 | 低影响且可可靠撤销操作反复确认 | 优先直接执行并给足可达撤销入口 |
| 8 | 全部字段错误只报一条Message | 字段错误关联字段，必要时加汇总 |
| 9 | 已明显可见的变化反复弹无用成功提示 | 保留必要状态反馈，减少重复打扰 |
| 10 | 同一表单标签关系混乱 | 按信息分组统一标签布局与关联 |
| 11 | 用opacity覆盖整块禁用组件 | 沿用目标组件的disabled与派生Token，不用整块opacity覆盖 |
| 12 | 比较数值难以纵向扫描 | 数字对齐并使用等宽数字，标识文本另处理 |
| 13 | 提交期间能连续重复请求 | 同步防重、loading和服务端幂等/去重 |
| 14 | 批量部分失败只显示“失败” | 区分成功/失败项并给恢复路径 |
| 15 | 状态仅由色点表达 | 提供可理解的文字/图标语义 |
| 16 | 完整对象详情塞进狭小确认框 | 整页或足够容量面板，保留回访入口 |
| 17 | 必需选择控件只有hover才出现 | 常驻或提供可发现、键盘可达入口 |
| 18 | 需要同时操作主页面却被Drawer遮罩阻断 | 验证并排/行内/无阻断面板的实际行为 |

## 第 7 章 表单设计细则

> 第 6 章解决"用什么容器装表单"，本章解决"容器里的表单具体怎么排、怎么校验、怎么提交"。
> 以Ant Design Form/Form.Item描述字段结构；API按目标工程版本。以下布局数值为项目默认，标签间距12px覆盖SDK默认verticalLabelPadding。

### 7.1 表单结构

#### 7.1.1 骨架

```
┌─ 页面标题区 ────────────────────────────────┐
│ ← 返回   创建订单                            │
│          一句话说明这张表要干什么（可选）        │
├──────────────────────────────────────────────┤
│                                              │
│  ── 分组标题 ────────────────────────────── │
│  标签 *                                      │
│  ┌────────────────────────────┐             │
│  │ 控件                        │ ← 宽 400/100%│
│  └────────────────────────────┘             │
│  帮助文本（12px，colorTextTertiary）                     │
│                                              │
│  标签 *                                      │
│  ┌────────────────────────────┐             │
│  └────────────────────────────┘             │
│                                              │
├──────────────────────────────────────────────┤
│  [保存草稿]  [创建订单]                       │  ← 组左对齐、主动作在右
└──────────────────────────────────────────────┘
```

#### 7.1.2 尺寸规范

| 项目 | 值 | Token |
|---|---|---|
| 表单容器最大宽度（单列） | **640px** | — |
| 表单容器最大宽度（双列） | 880px | — |
| 标签与控件间距 | 12px | `--ui-space-12` |
| **字段与字段间距** | **24px** | `--ui-space-24` |
| 控件与帮助/错误文本间距 | 4px | `--ui-space-4` |
| 分组与分组间距 | 32px | `--ui-space-32` |
| 分组标题与首字段间距 | 16px | `--ui-space-16` |
| 操作区与字段区间距 | 32px | `--ui-space-32` |

连续文本表单可参考单列640px/双列880px最大宽；表格、媒体、编辑器或窄容器应按任务伸缩。左对齐是推荐模板，不是Ant Design唯一允许方式。

### 7.2 字段规范

#### 7.2.1 字段宽度档位

| 档 | 宽度 | 适用 |
|---|---|---|
| 短 | 240px | 数量、金额、百分比、日期（单个）、编号 |
| 常规 | 400px | 名称、标题、短描述（单列时可用 100%） |
| 长 | 100% | 长文本、Textarea、富文本、上传区 |

**规则**：
- 同一行内并排的同类字段**宽度必须一致**
- 240/400/100%是项目宽度候选；其他280/320/360等按内容与容器确定的宽度均可使用，不因数值不在三档而打回
- 双列布局时每列宽度相等，用栅格（12 列，每列占 6）

#### 7.2.2 必填标记

- 用红色 `*` 置于**标签文字之前**，颜色 `--ui-color-error`
- **可选字段不做任何标记**——不要给每个可选字段加"选填"（视觉噪音）
- 全部字段都必填时，可省略 `*`，改为在表单顶部注明"以下均为必填项"
- 实现：标签/校验/可访问必填状态同步配置；具体Form.Item属性以工程类型为准

#### 7.2.3 帮助文本

- 位置：控件下方，12px（`--ui-font-size-xs`），色 `--ui-color-text-tertiary`
- 内容：说明"填什么"或"有什么限制"，一句话，≤30 字
- 必要信息放可见说明或可达帮助；Tooltip应支持focus且仅作补充，不能假设所有Tooltip都天然键盘不可达
- 错误就近显示；必要格式说明在错误后仍应可获取。可调整布局避免重复，但不以互斥规则隐藏修正错误必须的帮助

#### 7.2.4 占位符

| 用法 | 判定 |
|---|---|
| 示意格式 | ✅ 用：`YYYY-MM-DD`、`13800138000`、`示例：技术部` |
| 代替标签 | ❌ 禁止：标签缺失、只用占位符说明字段含义 |
| 重复标签 | ❌ 禁止：标签"姓名" + 占位符"姓名" |
| 承载必要规则 | ❌ 禁止：把"至少 8 位，含大小写"写在占位符里（填字后看不见了），应放帮助文本 |

#### 7.2.5 默认值与单位

- **能预判就给默认值**（当前日期、当前用户、上一次的选择），这是减少填写量的最有效手段
- 涉及金额、权限、生效时间的字段，默认值需业务方确认后才可以给
- 单位放**标签括号**或控件 `suffix`：`金额（元）`、`占比 %`，**禁止**写在占位符里
- 数字字段单位通过标签或目标InputNumber支持的前后缀表达；不得假设不同库同名props可直接复制

#### 7.2.6 字段顺序

1. 按**用户的填写心智**排序（先填什么、后填什么），不是按数据库字段顺序
2. 必填在前，选填在后
3. 有依赖关系的字段：被依赖的在前
4. 同类字段聚为一组（如所有地址字段连续）
5. 依赖未满足的字段**置灰禁用**（如未选"类型"时"子类型"禁用），而不是允许用户填了再报错

### 7.3 校验时机与错误呈现

#### 7.3.1 校验时机

| 时机 | 行为 |
|---|---|
| 输入过程中 | **不报错**（禁止打一半就变红） |
| 失焦 blur | 一般完成输入后的首次校验；具体触发配置按工程组件 |
| 值变化时 | 已出现错误时重新校验；仅在当前值通过对应规则后清除，不因任何修改就假装有效 |
| 提交时 | 全量校验 |

**例外（允许实时反馈）**：
- 密码强度提示：实时，但用**进度条/中性提示**，不用"错误"样式
- 唯一性查重（工号、编码是否已存在）：**debounce 500ms** 后异步校验，loading 态显示"检查中…"

#### 7.3.2 错误呈现

- 位置：**控件正下方**，12px，`--ui-color-error`，带警示图标
- 控件边框同步变 `--ui-color-error`
- 多个字段同时出错时**全部显示**，不要只显示第一个
- 提交失败时：
  - 自动**滚动到第一个错误字段**并聚焦
  - 表单顶部出现 Alert："有 N 项需要修改"（仅当错误字段不在首屏时）

#### 7.3.3 成功态

- 一般不显示绿色对勾（密集表单里会变成视觉噪音）
- 例外：密码强度达标、唯一性检查通过时，显示一次性正向反馈

### 7.4 提交与保存

#### 7.4.1 操作区

| 容器 | 对齐 | 顺序 |
|---|---|---|
| 独立表单页 | 操作组左对齐 | 次操作在左、主要动作在右，遵循所选模板 |
| 弹窗 / 抽屉 | 右对齐 | 次按钮在左，主按钮在右 |

- 按钮文案用**具体动词**："创建订单""保存修改"，避免语义不清的泛用词
- 主按钮数**只能有一个**；次操作最多 2 个，超出收进"更多"

#### 7.4.2 提交流程

1. 点击提交 → 按钮立即 `loading` + **禁用**（防重复提交是底线）
2. 校验失败 → 恢复按钮，错误就近显示（见 7.3.2）
3. 提交成功 → 弹窗/抽屉关闭并刷新列表；独立页跳转结果页或详情页
4. 提交失败（服务端错误）→ **保持表单不关闭、数据不丢**，顶部 Alert 显示服务端错误

通常允许点击提交再展示校验错误；权限不足、提交中、必要依赖未就绪等确实不可执行时可禁用，并在附近说明原因。不要让用户猜为什么不可用。

#### 7.4.3 草稿与自动保存

| 条件 | 策略 |
|---|---|
| 简短且可轻易重填 | 可不提供草稿，按中断成本决定 |
| >20 字段，或预计填写 >2 分钟 | **自动保存草稿**，显示"已自动保存 14:32" |
| 富文本 / 多附件 / 中断成本高 | 优先持久化草稿；明确存储、恢复与权限边界 |

- 自动保存间隔：停止输入后 3s，或每 30s
- 离开拦截：有未保存改动时，路由跳转 / 关闭弹窗必须二次确认"有未保存的修改，确定放弃？"
- **谨慎提供"重置"按钮**：误触会清空全部输入。建议改为"恢复默认值"，或直接不提供

### 7.5 长表单拆解策略

| 任务特征 | 默认策略 |
| --- | --- |
| 简单连续填写 | 单列单页，无需为少量字段强分组 |
| 存在自然信息类别 | 分组；组标题说明内容，关键/出错分组保持可见 |
| 阶段有依赖且可分批完成 | 分步；明确当前步、总进度、返回和保存 |
| 次要/高级内容 | 可折叠，但必要错误能被展开定位 |

复杂分步优先独立页；每步围绕一个阶段，不规定统一8字段。返回保留数据，切步按任务需要保存草稿；最后一步才执行最终提交。不能让切换步骤、刷新或离开提示隐瞒数据是否保存。

### 7.6 只读态、禁用态与权限

#### 7.6.1 三种状态必须区分

| 状态 | 含义 | 行为 |
| --- | --- | --- |
| 只读 | 已授权查看，当前不编辑 | 可用纯文本/Descriptions；需要输入样式时用支持的readOnly。文本应可选取复制，不给每段静态文字都加Tab停靠 |
| 禁用 | 当前控件不可执行 | 原生disabled控件通常不进入Tab顺序；不能承诺可聚焦/可复制。帮助信息放在可达位置，不能只挂在不能聚焦的控件上 |
| 无编辑权限但可查看 | 值可见但无修改权 | 纯文本或只读，并按需要说明 |
| 无查看权限 | 不得披露值 | 隐藏/脱敏/权限说明；服务端不返回无权数据 |

不要仅用disabled低对比表现详情值。`aria-disabled`并不自动阻止事件；如用它保留焦点，需正确实现不可执行逻辑。静态文本与可聚焦readOnly输入不是同一个行为模型。

#### 7.6.2 权限不足的呈现

**本条是权限入口隐藏/禁用的负责条款**，列表行操作等引用本条。

| 条件 | 默认呈现 | 需要明确的内容 |
| --- | --- | --- |
| 无查看权 | 不展示无权值；必要时显示范围说明或返回路径 | 服务端不返回无权内容；可申请时才展示真实申请入口 |
| 有查看权、无操作权，且需要发现/协作/申请该能力 | 保留不可执行入口及可达原因，或提供实际可用的申请/联系路径 | 说明谁可操作、如何获得帮助；权限信息本身也须允许披露 |
| 无操作权，且无合理的发现、协作或恢复用途 | 隐藏该动作 | 页面仍能完成用户有权执行的任务 |
| 有操作权，当前业务条件暂不满足 | 条件可能改变且说明有助下一步时禁用；永久不适用于该对象的动作可隐藏 | 给出业务条件，不把业务状态写成无权限 |
| 提交中或依赖尚未就绪 | 临时不可执行并显示相关进度/原因 | 结束后恢复或给出真实错误及恢复方式 |

先判断查看权，再判断操作权和入口的任务价值；不采用“所有无权限动作都隐藏”或“所有不可执行动作都置灰”的统一捷径。需要的原因说明应可见或键盘/触屏可达，不只挂在原生disabled按钮的hover Tooltip上。

前端表现不替代服务端鉴权。申请、转交、复制等替代入口仅在真实支持且用户有权使用时提供；演示必须说明范围，不伪造权限变更成功。

### 7.7 键盘流

| 按键 | 行为 |
|---|---|
| Tab / Shift+Tab | 按**视觉顺序**移动，禁止用 `tabindex` 强行改序 |
| Enter（单行控件内） | 按表单任务触发预期动作；选择器/组合输入/中文输入法确认中不得误提交，搜索框触发查询 |
| Enter（Textarea 内） | 换行；可选Ctrl/Cmd+Enter快捷提交须明确提示，不能作为唯一提交方式 |
| Esc | 弹窗 / 抽屉内取消（有未保存内容则拦截，见 6.4.4）；独立页面不响应 |
| Space | 勾选框切换；按钮触发 |

**焦点可见性**：
- 聚焦环用 2px `--ui-color-primary` outline，偏移 2px
- 不得移除唯一可见焦点；可替换原outline，但要提供等效的focus-visible指示
- 可执行提交按钮应键盘可达；提交中或合法禁用期间按组件语义处理，附近提供可读状态

### 7.8 表单文案模板库

#### 7.8.1 错误文案：说"怎么改"，不说"你错了"

| ❌ 不要这样 | ✅ 要这样 |
|---|---|
| 格式错误 | 请输入 11 位手机号 |
| 不能为空 | 请填写部门名称 |
| 输入不合法 | 仅支持字母、数字和下划线 |
| 已存在 | 工号 A1024 已被占用，请更换 |
| 超出限制 | 最多可选择 5 项 |
| 日期错误 | 结束日期不能早于开始日期 |

**必填错误统一句式**：
- 输入类：`请填写{字段名}`
- 选择类：`请选择{字段名}`
- 上传类：`请上传{文件名}`

#### 7.8.2 帮助文本句式

- `用于{用途}`：用于登录时的身份校验
- `支持{格式/范围}`：支持 JPG、PNG，单个不超过 5MB
- `{默认行为}`：留空则默认跟随上级部门
- 一句为限，需要长说明时改用"了解更多"链接

#### 7.8.3 提交与危险确认句式

- 提交按钮：`{动词}{对象}` → 创建订单、保存修改、提交审批
- 危险确认：`{动作}{对象名}？{后果}` → 删除技术部？该部门下 8 名成员将被移出
- 批量：必须带数量 → 删除选中的 12 项

## 第 8 章 数据展示与表格

> 表格是 B 端后台最高频的元素。组件规格见 5.5.1，页面骨架见 4.2.1，本章写**数据层面的规则**。

### 8.1 列策略

#### 8.1.1 列顺序

从左到右固定为：

```
[☑] 标识列 → 主要属性 → 状态列 → 数值列 → 时间列 → [操作]
 固定左                                              固定右
```

| 位置 | 内容 | 是否固定 |
|---|---|---|
| 最左 | 复选框（如需批量操作） | 固定 |
| 左 | **标识列**：ID / 编号 / 名称 | **固定左** |
| 中 | 主要属性、描述 | 滚动 |
| 中 | 状态列 | 滚动 |
| 右 | 数值列、时间列 | 滚动 |
| 最右 | 操作列 | **固定右** |

**规则**：表格出现横向滚动时，标识列与操作列必须保持可见（固定列API按实际工程版本）。

#### 8.1.2 列宽与对齐

| 内容类型 | 对齐 | 宽度策略 | 字体 |
|---|---|---|---|
| 文本（名称、描述） | **左** | 自适应 + 超出省略 | 常规 |
| 数值（金额、数量） | **右** | 固定宽 | **等宽数字或适当等宽字族** |
| 状态（Tag、状态点） | 默认左对齐，窄工具列可居中 | 按内容约束 | 常规 |
| 时间 | 左 | 固定宽（按格式长度） | 等宽数字或适当等宽字族 |
| 操作 | **右** | 固定宽（按最长组合） | 常规 |

**规则**：
- 比较数值使用tabular-nums并右对齐；全等宽字族并非唯一方案，编号/电话作为文本标识处理
- 单位写进**表头**（`金额(元)`、`占比(%)`），不要在每个单元格重复
- 长文本按空间选择换行或截断；完整信息应可通过focus提示、展开、复制或详情获取，不能只提供hover
- 表头文案 ≤6 字，用名词，不加"该/的"
- 普通表格正文统一使用`colorText`（静态CSS别名`--ui-color-text`）；创建时间、更新时间等独立时间列与其他普通正文列保持一致，不因字段是时间就改成次级/弱化色或缩小字号。语义状态、风险提示、可操作链接、禁用态及单元格内真正的副信息按各自规则处理，不能将整个时间列当作副信息。

#### 8.1.3 列数与单元格

- 默认展示任务核心列；较多列时可提供列设置和横向滚动，不把8列设为组件硬上限，也不隐藏必需信息
- **禁止**在一个单元格内堆叠多个属性（如"姓名 / 部门 / 工号"挤一格）。需要主副信息时用两行：主行 `colorText`、副行 `colorTextTertiary` 12px

---

#### 8.1.4 固定列分隔阴影

固定列阴影用于提示被固定列遮住的横向滚动内容，按实际溢出和滚动位置显示。固定列存在本身不构成显示阴影的条件，禁止给操作列长期附加装饰性阴影。

| 当前状态 | 右侧操作列左边缘的分隔阴影 |
| --- | --- |
| 全部列已在表格可视宽度内完整展示，无横向溢出 | 隐藏 |
| 有横向溢出，右侧固定列仍遮住尚未滚入可视区的内容 | 显示 |
| 已滚动到最右端，右侧已无剩余被遮挡内容 | 隐藏 |
| 操作列已取消固定（如窄屏采用普通列），或列表为空 | 隐藏 |

- 测量表格自身滚动容器的`scrollWidth`、`clientWidth`和`scrollLeft`，不能只判断浏览器宽度或固定列配置。`clientWidth`已排除占位滚动条，不用外框宽度代替。
- 阴影判定（从左向右布局）：`maxScroll = max(0, scrollWidth - clientWidth)`；只有固定仍生效、存在数据、`maxScroll > ε`且`maxScroll - max(0, scrollLeft) > ε`时显示右侧阴影。项目默认`ε = 1 CSS px`以容忍缩放与小数舍入。
- 如采用左侧固定列分隔阴影，仅在左侧已滚过、仍有被固定列遮挡的内容时显示；未开始横向滚动时隐藏。
- 表头与表体采用同一状态。滚动、窗口缩放、导航/分类面板收展、列显隐或列宽变化、数据渲染/分页/空态切换后均应重新判断，溢出消失后及时移除残留阴影。
- 优先复用目标SDK的滚动状态能力；自定义HTML可用被动滚动监听、`ResizeObserver`及按帧合并更新。保留组件本身必要的背景和边框，不靠永久阴影代替分隔。
- “横向滚动查看全部字段”等提示只在实际存在横向溢出且有数据时显示。

### 8.2 排序、筛选、搜索

#### 8.2.1 三种检索方式的分工

| 方式 | 位置 | 适用 | 生效时机 |
|---|---|---|---|
| **搜索** | 筛选区（表格上方） | 关键词模糊匹配 | 回车或点"查询" |
| **筛选区条件** | 筛选区 | 跨字段条件、日期范围 | 有“查询”按钮时整组统一应用；即时筛选模式则明确标记，避免混合半生效 |
| **列筛选** | 表头 dropdown | 枚举值（状态、类型） | 立即生效 |

#### 8.2.2 排序规则

- 可排序列：时间、数值、有明确顺序的状态
- 三态循环：无 → 升序 → 降序 → 无
- **默认排序：时间倒序**（最新的在前），除业务另有要求
- 排序仅对当前筛选结果生效
- **禁止**给操作列、复选框列排序

#### 8.2.3 组合规则

- 筛选条件常驻 **≤4 个**，超出收进"高级筛选"（展开面板）
- 筛选区每行默认≤4个筛选项；同一容器宽度/响应式断点下，关键词、选择器等普通筛选项使用同一组等宽栅格，控件填满所属列，不能单独加宽关键词列。
- 收起与展开状态共用相同的字段列宽计算；高级筛选行与首行的列起点、列宽、列间距一致，行/列间隙默认12px。末行不足一整行时保留空位，不将剩余项自动拉伸填满；禁止上下两行分别按不同可用宽度计算列宽。
- 查询、重置及展开/收起入口使用独立操作位或独立操作行，不计入筛选字段的等宽列；操作位需要占宽时，对所有筛选行统一预留，不能只挤压首行字段。
- 空间不足时整组切换为较少的等宽列，窄屏可改为单列；不能用不等宽列挤放字段。确有跨列需求时按0.3明确适用范围，默认普通筛选项等宽。
- 筛选后立即显示结果数："共 N 条"
- 提供“重置”，恢复已定义默认条件；如意图清空全部值则用“清空”，不要混淆两者
- 可分享/回访列表将非敏感筛选、排序、分页状态写入URL；敏感值不直接放查询串，可使用服务端保存视图ID等方式。仅使用本地状态的页面明确可恢复范围与分享能力

#### 8.2.4 列表操作后的状态处理表

一次列表上下文包含：业务分组/数据范围、已应用筛选、尚未提交的筛选输入、排序、页码、每页条数、稳定ID选择集、横纵滚动位置与焦点返回目标。保存/返回按这个整体判断，避免只恢复页码。

默认使用当前页选择。下表适用于未另定选择策略的列表；已支持的跨页选择需明确入口、数量和作用范围，按6.7处理。

| 事件 | 分组、筛选与排序 | 页码 / 每页条数 | 选择集 | 滚动与焦点 |
| --- | --- | --- | --- | --- |
| 输入筛选但未查询 | 已应用条件及结果不变，仅更新草稿输入 | 不变 | 不变 | 保留输入焦点 |
| 查询 / 应用筛选 | 整组提交；保留当前分组及排序 | 第1页；条数保留 | 清除当前页选择 | 结果区可见并播报数量；输入校验失败定位字段 |
| 重置筛选 | 恢复当前分组定义的默认筛选；默认保留分组及排序 | 第1页；条数保留 | 清除 | 结果区顶部；焦点保留在触发入口或合理后继位置 |
| 切换分组 / 分类 | 保留兼容的公共筛选与排序；不适用条件清除并说明 | 第1页；条数保留 | 清除 | 列表顶部；焦点留在当前分组/分类入口 |
| 改变排序 | 当前已应用筛选与分组不变 | 第1页；条数保留 | 清除当前页选择 | 列表顶部；排序控件状态可读 |
| 翻页 | 不变 | 进入目标页；条数保留 | 清除当前页选择 | 表格顶部；键盘触发时默认聚焦列表标题并播报页码 |
| 改变每页条数 | 不变 | 第1页；更新条数 | 清除 | 表格顶部 |
| 列显隐 / 列宽 / 面板收展 | 不变 | 不变 | 记录范围不变时保留 | 滚动位置夹取到新边界，重新判断固定列阴影 |
| 打开编辑 / 取消编辑 | 不改变列表上下文；未保存内容按6.4.4处理 | 不变 | 保留有效ID | 保留横纵位置；关闭后返回原触发元素 |
| 保存后记录仍在结果中 | 保留分组、已应用筛选及排序，按实际新值更新 | 尽量保留；超界才校正 | 保留仍在当前页的有效ID | 保留原位置或可用记录锚点；显示保存结果 |
| 保存/转交/归档后记录离开结果 | 保留当前条件，移除不再匹配记录；不自动放宽条件 | 夹取到有效页；条数保留 | 移除已离开结果的ID | 当前位置夹取到有效范围；原按钮消失时返回列表标题，说明记录去向 |
| 批量全部成功 | 保留当前条件并刷新相关数据 | 校正有效页 | 清除已成功处理项 | 保持上下文，说明成功数量 |
| 批量部分失败 / 结果未知 | 不改条件，不将已成功项重发 | 校正有效页 | 已成功项移除；失败的可见项保留；未知项先查状态 | 展示明细和真实恢复入口，按9.4执行 |
| 从详情返回列表 | 恢复进入详情前的上下文 | 恢复有效页及条数 | 恢复有效ID | 恢复滚动锚点和原入口；目标已消失时使用合理后继焦点 |
| 刷新当前结果 | 使用当前已应用条件，不丢未提交输入 | 保留有效页及条数 | 以稳定ID与当前数据核对，移除失效项 | 保留有效位置；局部加载/错误不清空整页状态 |
| 导出 | 按动作明确的当前页、当前结果或已选范围；保留权限限制 | 不影响列表 | 不改变 | 保留当前上下文，给出文件/任务真实结果 |

补充规则：

- “重置筛选”与“恢复整个视图”是不同动作。需要同时恢复排序、列设置、条数时明确命名和说明，不暗中扩大重置范围。
- 记录数为0时保留表头和当前条件，展示相应空态；内部分页可记第1页，不能显示可点击的非法页码。
- 当前页选择在任何结果重排后都要重新核对，不能以数组下标选择；查询失败不将原选择错误映射到其他记录。
- 列表删除/归档/恢复遵循相同范围校正原则。恢复记录后不默认跳到其他模块；需要引导查看时提供明确入口。
- 切换模块、浏览器返回及刷新是否持久恢复，需明确；支持分享的非敏感视图状态按8.2.3编码，本地状态页面不承诺服务端分享。草稿筛选与已应用筛选分别保留。
- 导出入口应明确“导出当前结果（N项）”“导出当前页（N项）”或“导出已选（N项）”；长任务可在菜单/任务说明中表达范围。数量未知时不编造总数，已有明确范围无需重复增加确认步骤。
- 未保存离开、后台任务和结果未知按6.4、6.8、9.4处理，本表不代替这些保护规则。

### 8.3 分页 vs 滚动加载 vs 虚拟滚动

| 数据特征 | 方式 | 说明 |
|---|---|---|
| 常规业务列表（默认） | **分页** | 支持定位、返回、分享 |
| 需同屏对比多行 | 分页 + 大页容量（50/100） | |
| 信息流、时间线、日志 | 滚动加载 | 无明确终点 |
| 单页 >200 行 | **虚拟滚动** | 避免 DOM 过多卡顿 |
| 需导出全量 | 分页 + 导出 | 导出不受分页限制 |

**分页规格**（项目默认；具体API按工程Pagination）：
- 默认每页 **10** 条；可选 10 / 20 / 50 / 100
- 显示"共 N 条"；>10 页时开启快速跳页
- 切换页码时**保留筛选与排序条件**
- 翻页后滚动到表格顶部；焦点、选择与页码校正按8.2.4

**滚动加载规则**：每次加载 ≤20 条；到底显示"没有更多了"；**禁止**无限自动加载（用户失去位置感），需提供"回到顶部"。

### 8.4 表格四态

> 四态都必须**保留表头可见**（无权限态除外），否则用户不知道这张表是什么。

| 状态 | 呈现 | 操作 |
|---|---|---|
| **加载中** | 首次加载用**骨架屏**（行数 = 当前页容量）；刷新用表格上方细进度条或局部 Spin | 无 |
| **空 · 无数据** | Empty 插画 + "暂无数据" + **主操作**（如"新建订单"） | 新建 |
| **空 · 筛选无结果** | 空状态 + "没有找到符合条件的结果" + **"重置筛选"** | 重置 |
| **错误** | 错误图标 + "加载失败" + **"重试"** | 重试 |
| **无权限** | 说明范围，表体不披露无权数据 | 有真实申请流程时申请，否则返回/联系路径，见7.6.2 |

**⚠️ 关键区分**：「无数据」和「筛选无结果」是**两种空状态**，必须分开。筛选无结果时引导用户"重置筛选"，而不是让他去"新建"——他已经建过了，只是被筛掉了。这是最常见的空状态错误。

**规则**：
- 加载态的行数要与真实内容高度接近，避免加载完成时页面大幅跳动
- 骨架屏保留表头，只替换表体
- 错误态必须给"重试"，不能只显示一句失败

---

### 8.5 行内操作与操作列

- 位置：最右，固定列；分隔阴影按8.1.4随溢出与滚动边界切换，空间足够时不显示
- **数量上限 2 个**文字按钮，超出收进"更多"（Dropdown）
- 高频操作前置（查看 / 编辑），**危险操作（删除）放进"更多"**，不要直接暴露在行内
- 列表“编辑”默认打开当前对象的表单Modal，按6.4.8执行；复杂任务的Drawer/独立页例外需有明确依据
- 操作列宽固定，按最长组合计算，避免切换页面时列宽跳动

**禁用 vs 隐藏**统一按7.6.2：先区分查看权、操作权及业务条件，再判断入口是否有发现、协作或恢复用途。保留的不可执行入口提供可达原因，权限不足不一律隐藏；原生disabled入口也不能只依赖hover解释。

**规则**：
- 操作优先明确文字；纯图标必须有可访问名称，Tooltip可提供可见解释，不能作为唯一名称
- 点击行内操作**不要整行跳转**——整行点击与行内操作并存会让用户误触
- 若支持"点击整行进入详情"，则行内操作点击需 `stopPropagation`

### 8.6 图表规范

#### 8.6.1 图表类型选用对照表

| 分析目的 | 图表 |
|---|---|
| 趋势 / 随时间变化 | **折线图** |
| 少量类别的整体占比 | 饼图 / 环形图，优先少量可读扇区 |
| 较多类别的整体占比 | 排序条形图；需要整体构成时评估堆叠条形图 |
| 数值对比（类目 ≤12） | 柱状图 |
| 数值对比（类目 >12） | **横向条形图** |
| 排名 | 横向条形图 |
| 相关性 | 散点图 |
| 分布 | 直方图 |
| 流程 / 转化 | 桑基图、漏斗图 |
| 单一完成度 / 占比 | 优先Progress/Statistic；有明确业务理由时再用仪表盘/水波图扩展 |

#### 8.6.2 配色与元素规格

| 元素 | 规格 |
|---|---|
| 配色 | 走 3.3.6 分类色板；**同一指标在不同页面颜色必须一致** |
| 坐标轴 | 轴标签 12px `--ui-color-text-tertiary`；网格线 `--ui-color-border-secondary`；轴线 `--ui-color-border` |
| 图例 | 右上或底部，**不得遮挡数据**；可点击切换显隐 |
| Tooltip | 显示维度名 + 完整数值 + 单位；数值不缩写 |
| 数据点标记 | 数据点 >50 时关闭（折线图） |
| 数值标签 | 柱形图可选显示；折线图默认不显示 |
| 空数据 | 图表区居中显示"暂无数据"，坐标轴不隐藏 |

**规则**：
- 图表区最小高度 200px
- 切换时间范围/筛选时，**图表高度不变**（避免布局跳动）
- 数值精度：金额 2 位小数，百分比 1 位，整数不带小数

#### 8.6.3 禁用项

- ❌ 3D 图表（透视会扭曲数值对比）
- 不默认使用双Y轴；确有分析理由时说明单位、范围与比较方式，优先分面图
- 避免切片过多导致标签不可读；聚合或改图型，不用类别数代替可读性验证
- ❌ 彩虹配色（用固定色板，不用连续色相铺满）
- ❌ 截断 Y 轴制造差异（除非明确标注轴不从 0 开始）
- ❌ 无坐标轴的柱状图（无法判断数值）

### 8.7 指标卡与数字展示

#### 8.7.1 数值格式规则

| 场景 | 规则 | 示例 |
|---|---|---|
| 整数 | 千分位分隔 | 1,234,567 |
| 大数值 | ≥6 位自动缩写，hover/focus或可达详情显示完整值 | 123.4 万 |
| 金额 | 默认2位小数；独立值明确币种/单位，同币种表格可按8.1.2在表头统一声明 | ¥1,200.00 / 金额（元） |
| 百分比 | 1 位小数 | 12.5% |
| 未知/缺失值 | 显示 `--`；真实数值0仍显示0 | `--` / 0 |
| 整数型度量 | 不显示小数；金额等固定精度不因末尾为0就省略 | 120 / ¥120.00 |

未知/缺失值显示`--`，真实0显示0；空列表可为0条记录，不能把所有“无数据”都转成未知数值。

#### 8.7.2 指标卡结构

```
┌──────────────────┐
│ 今日 GMV          │  ← 标签 14px colorTextSecondary
│                  │
│ ¥1,234.5         │  ← 数值 默认24/32（字号/行高），对齐数字，colorText
│ ↑ 12.5% 较昨日   │  ← 同比环比 12px
└──────────────────┘
```

| 元素 | 规格 |
|---|---|
| 标签 | 14px，`--ui-color-text-secondary`，单行截断 |
| 数值 | 默认24px/32px行高，必要时30px/38px行高；对齐数字，`--ui-color-text` |
| 单位 | 比数值小一档，间距 4px |
| 同比环比 | 有可比基期时提供；12px，按8.7.3定义口径及业务好坏配色，并提供↑/↓ |
| 迷你图 | 可选，高度 ≤40px，不抢主数值视觉 |
| 卡片 | Ant Design默认Card圆角8px、body24px；紧凑或业务覆盖单列 |

**规则**：
- 同一行指标卡的**数值基线必须对齐**——数值字号一致、卡片等高
- 涨跌颜色按方向、指标好坏和业务语境配置；不用金融惯例覆盖普通考培/运营指标
- 一屏指标卡 ≤6 个（看板页）或 ≤4 个（首页一行）

#### 8.7.3 指标口径、时间范围与联动

指标须具备下表定义，并使用8.7.1的数字格式。口径未定义时仅展示已定义的列表结果数，不编造公式或趋势。

| 定义项 | 必须说明的问题 |
| --- | --- |
| 名称与对象 | 计数的是客户、订单、任务还是金额？界面名称与单位是否准确？ |
| 可见范围 | 个人/团队/组织/全局哪个范围？始终受当前用户查看权限限制 |
| 纳入与排除 | 是否包含公海、归档、取消、停用等记录；按什么稳定标识去重 |
| 时间与时区 | 统计时点或时段；时间字段、起止边界、时区及日期/时刻精度 |
| 公式与精度 | 分子、分母、汇总方式、单位；分母为0、缺失与真实0如何处理 |
| 新鲜度 | 数据来源、截至时间或更新方式；静态演示不显示虚假的实时更新状态 |
| 比较值 | 同比/环比的基期及可比性；无有效基期时省略或显示明确的不可比较状态 |
| 筛选关系 | 是否继承业务分组、已应用筛选；未提交的筛选输入不改变指标 |
| 点击行为 | 是否可点击；目标视图、带入条件与可返回路径；无目标时不提供伪入口 |

指标与列表不共用口径时，在标题、说明或可达帮助中表达区别，例如“团队客户概况”与“当前筛选结果”。筛选无结果时，独立的团队指标可保留，但不能让用户误认其为结果数。指标点击改变结果时按8.2.4处理页码、选择和焦点。

## 第 9 章 全局状态与异常

> 8.4 讲的是**表格内**的四态，本章讲**整页与区块级**的状态处理。
> 核心原则：**局部问题不要升级成全局阻塞。**

### 9.1 四态体系

| 状态 | 视觉呈现 | 操作 |
|---|---|---|
| **加载 Loading** | 骨架屏（首次）/ 局部 Spin（刷新） | 无 |
| **空 Empty** | 插画 + 一句说明 + 最多 1 个主操作 | 新建 / 重置筛选 |
| **错误 Error** | 图标 + 一句说明 + 重试 | 重试 / 返回 |
| **无权限 No-Permission** | 说明范围；申请入口按7.6.2提供 | 真实可用的申请/联系路径或返回 |

#### 9.1.1 状态粒度规则

按**故障范围**决定呈现范围，不要一刀切：

| 情形 | 处理 |
|---|---|
| 整页首次加载 | 整页骨架屏 |
| 单个区块加载 | **仅该区块骨架屏，其他区块正常渲染** |
| 关键数据请求失败 | 整页错误态 + 重试 |
| 次要数据请求失败 | **该区块内降级显示"暂不可用"，页面其余部分照常可用** |
| 多个区块同时失败 | 按是否导致主任务整体不可用判断；独立次要区块可分别降级 |

**⚠️ 常见错误**：一个次要接口挂了，整页就白屏或整页报错。用户会以为系统坏了。正确做法是**降级而非阻塞**。

#### 9.1.2 空状态文案公式

```
无数据：      "暂无{对象}"          + [新建{对象}]
筛选无结果：  "没有找到符合条件的{对象}" + [重置筛选]
搜索无结果：  "未找到「{关键词}」相关结果" + [清空搜索]
无权限：      "你没有查看{对象}的权限" + [真实可用的申请入口 / 返回]
```

**规则**：空状态说明必须**说清是什么空、为什么空**，不能只写"暂无数据"。

### 9.2 骨架屏 vs 转圈

| 维度 | Skeleton 骨架屏 | Spin 转圈 |
|---|---|---|
| 适用 | 首次加载、整块内容未就绪 | 局部刷新、已有内容上的操作 |
| 优势 | 保留布局，无跳动 | 轻量 |
| 禁止 | 长期（>3s无解释且无恢复路径）占位不结束 | 整页长期转圈 |

**规则**：
- 骨架屏的形状要**接近真实内容**（行数、高度），否则加载完成时仍会跳动
- 加载 >3s 时，骨架屏上叠加"加载中…"文字，避免用户以为卡死
- **禁止**整页长期转圈（>3s 未出内容）

### 9.3 错误分级与可恢复路径

| 级别 | 示例 | 呈现 | 用户可做的事 |
|---|---|---|---|
| L1 字段级 | 必填未填、格式错 | 字段下方红字 | 就地修改 |
| L2 操作级 | 提交失败、删除失败 | Message / Alert + 重试 | 重试、修改后重试 |
| L3 区块级 | 某模块数据加载失败 | 区块内错误态 | 重试该区块 |
| L4 页面级 | 页面主数据失败 | 整页错误态 | 重试、返回列表 |
| L5 应用级 | 主任务整体不可用 | 应用级提示并保留可用导航/草稿 | 重连、返回或稍后再试 |

**规则**：
- 每一级错误都必须给出**下一步动作**（重试 / 返回 / 修改），**禁止**只报"操作失败"
- 错误信息要说明**失败原因**（"网络连接失败"优于"请求失败"），但不暴露技术细节（不显示错误码、堆栈给终端用户）
- 技术细节放在"查看详情"或直接写日志，不占主文案

### 9.4 网络异常、超时与部分失败

| 情形 | 处理 |
| --- | --- |
| 只读请求超时 | 保留可用内容，提示原因和重试；自动重试应有上限、退避和终止条件 |
| 写入请求超时/断网 | 结果可能未知，不直接标成失败并重发；先查任务/对象状态，使用幂等键或服务端去重机制 |
| 网络恢复 | 重查需要的数据，保留未保存输入；不自动整页刷新清空表单 |
| 部分失败 | 显示成功/失败项及恢复路径，错误明细只包含用户有权查看的信息 |
| 长任务 | 服务端持久化后提供任务ID与状态查询，避免前端离页就承诺任务一定继续 |

超时阈值与重试次数按接口语义配置，10s/最多1次是默认建议而非通用事实。无幂等保障的写入不得因结果未知自动重复提交。

### 9.5 404 / 500 / 维护页

| 页面 | 文案 | 操作 |
|---|---|---|
| 404 | "页面不存在或已被移除" | 返回首页、返回上一页 |
| 500 | "服务器开小差了，请稍后重试" | 刷新、返回首页 |
| 无权限 | "你没有访问该页面的权限" | 按7.6.2提供真实申请/联系路径或返回 |
| 维护中 | "系统维护中，预计 {时间} 恢复" | 无（或联系管理员） |

**规则**：错误页也要有导航出口，**禁止**只放一句话让用户卡死。

## 第 10 章 内容与微文案

### 10.1 语气与人称

- 对用户用"你"，**不用"您"**（B 端工具追求效率，敬语拉远距离，且全站统一才自然）
- 陈述句为主，少用感叹号
- 说"能做什么"，不说"系统不支持什么"
- 避免技术术语：用"导出表格"不用"生成 CSV"；用"恢复"不用"回滚事务"

| ❌ | ✅ |
|---|---|
| 您确定要删除吗？ | 删除订单 1001？删除后不可恢复 |
| 操作失败，请联系管理员 | 保存失败，请检查网络连接后重试 |
| 系统暂不支持该功能 | 说明当前可用替代路径；只有已确认计划才承诺下个版本上线 |

### 10.2 术语表

**同一概念在全站只能有一个叫法。** 下表为模板，业务术语需团队补齐后生效。

| 概念 | 统一叫法 | 禁止使用的别名 |
|---|---|---|
| 客户 | 客户 | 顾客、用户、商家 |
| 订单 | 订单 | 交易单、业务单 |
| 状态·已完成 | 已完成 | 结束、完结、done |
| 考试 / 培训 / 课程 / 练习 | 按产品真实业务对象分别命名 | 不用“用户/客户/记录”笼统替代不同对象 |

**规则**：
- 新增术语保持全站术语一致
- 代码、接口与界面术语通过映射保持同一业务含义，不强制内部标识字面相同
- 评审时重点检查"同一页面里同一个东西有两种叫法"

### 10.3 按钮动词表

| 动作 | 推荐文案 | 说明 |
|---|---|---|
| 创建 | 新建{对象} / 创建{对象} | 二选一，全站统一 |
| 修改 | 编辑 / 保存修改 | 页面内用"保存修改" |
| 删除 | 删除 | 配后果说明 |
| 提交 | 提交{对象} | 必须带对象 |
| 审批 | 通过 / 驳回 | 不写"同意/不同意" |
| 导入导出 | 导入 / 导出 | 导出可加对象："导出报表" |
| 组合筛选 / 关键词检索 | 查询 / 搜索 | 对应不同检索方式，同一语义保持一致 |
| 恢复默认筛选 | 重置 | 明确是否恢复默认值；“清空”用于确实清空当前值的不同动作 |
| 取消当前 | 取消 | |
| 上传 | 上传{文件类型} | |
| 启停 | 启用 / 停用 | 不写"激活/禁用" |

优先具体动词；语境清楚的“确定”“完成”“是/否”可以使用。避免无法判断动作后果的泛用词、重复的“确认提交”和把“点击”当作动作名称。

**规则**：按钮文案 = **动词 + 对象**，让用户不看上下文也知道会发生什么。

### 10.4 标题与说明句式

| 元素 | 句式 | 示例 |
|---|---|---|
| 页面标题 | 具体名词 | 订单列表、客户详情 |
| 区块标题 | 名词短语 | 基础信息、操作日志 |
| 弹窗标题 | 动词短语 | 删除部门、创建订单 |
| 说明文字 | 一句话说清用途或后果 | 删除后该部门下 8 人将被移出 |
| 空状态 | 什么空 + 为什么空 | 没有找到符合条件的订单 |

**禁止**：页面标题用"XX管理""XX信息"这类空泛词；弹窗标题用"提示""系统消息"。

### 10.5 数字、日期与单位格式

#### 10.5.1 数值

数值展示规则见 **8.7.1**（千分位、缩写、精度、无数据显示 `--`）。

#### 10.5.2 日期与时间

| 场景 | 格式 | 示例 |
|---|---|---|
| 列表 | `MM-DD HH:mm` 或 `YYYY-MM-DD` | 10-28 16:30 |
| 详情 | `YYYY-MM-DD HH:mm:ss` | 2026-10-28 16:30:00 |
| 日期区间 | `YYYY-MM-DD ~ YYYY-MM-DD` | 2026-10-01 ~ 2026-10-28 |
| 相对时间（近 7 天） | 今天 / 昨天 / 3 天前 | 今天 16:30 |
| 相对时间（>7 天） | 改用绝对日期 | 2026-10-01 |
| 精确到天 | `YYYY-MM-DD` | 2026-10-28 |

**规则**：
- 时间列用等宽数字或适当等宽字族（对齐）
- 相对时间只用于"距今很近"的场景，超过 7 天必须切绝对日期
- 默认展示Asia/Shanghai（北京时间）为项目默认；跨时区数据明确转换与来源，日期型字段不因时区误移一天

#### 10.5.3 单位

- 单位紧跟数值，间隔 4px，字号小一档
- 金额符号与数值间不加空格：`¥1,200.00`
- 百分比：`12.5%`（数值与 `%` 间不加空格）
- 复合单位统一：`万`、`亿`（中文场景），不用 `K`、`M`

### 10.6 多语言与截断

- 按目标语言和真实长文案测试布局，不将英文膨胀40%—100%当成通用保证
- 按钮、标签类元素**禁止固定窄宽**，用 padding 自适应
- 文本按任务选择换行/截断/横滚/展开；Tooltip支持focus，必要全文通过复制/详情等可达方式获取
- 截断位置：优先在末尾截断，保留前缀（用户靠前缀识别）
- 关键数字/日期/代码优先完整展示；代码可在合适位置换行或横滚，长标识可中间省略并提供复制/全文入口，不能让原值不可获取
