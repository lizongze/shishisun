# 事事顺 · 每日工作同步

把「git 提交」翻译成「事事顺事项的跟进日志」。提交由全局 post-commit hook 实时缓存成本地文件，本技能按固定流程读取缓存、匹配事项、写回记录。

**核心约束：只依据缓存里的真实提交写记录，不编造工作内容。**

## 运行环境

脚本是 shell 脚本，在**项目根目录**（DSH 会话的当前工作目录）用 Git Bash 执行，路径都用相对路径：

```bash
bash skills/shishisun/scripts/sync.sh <命令>
```

下文把 `bash skills/shishisun/scripts/sync.sh ...` 简写成 `sync.sh <命令>`。
如果当前工作目录不是本项目，脚本路径改用 `~/.dsh/skills/shishisun/scripts/...`（安装时建的用户级软链，指向同一份文件）。

> 不要用 PowerShell / cmd 里的 `bash`：Windows 上它指向 WSL，脚本会检测到并报错退出。若当前终端不是 Git Bash，先换成 Git Bash 再执行。
> Linux / macOS 直接用系统 bash 即可（脚本兼容 bash 3.2）。

## 安装（首次）

每台机器一次，完整步骤见 [INSTALL.md](INSTALL.md)。在项目根目录执行最小安装：

```bash
bash skills/shishisun/scripts/install-hooks.sh '<仓库上级目录>' -e '<用户本人的邮箱>'
```

邮箱是「谁的工作记录」的唯一依据，必须是用户自己的地址（不是示例、不是同事的）。
装完用 `sync.sh status` 确认 `email` 一行是用户本人，再在任意注入过的仓库提交一次验证缓存。
`uninstall-hooks.sh <仓库上级目录>` 可撤销（`--purge` 连配置缓存一起删）。

## 前置

| 项 | 位置 |
|----|------|
| 提交缓存 | `~/.dsh/shishisun/commits/commits-YYYY-MM-DD.tsv`（post-commit hook 写入） |
| 配置 | `~/.dsh/shishisun/config.sh`（邮箱、仓库→项目映射） |
| 状态 | `~/.dsh/shishisun/state/`（已处理提交、上次运行时间） |
| 脚本 | 本目录 `scripts/sync.sh`、`scripts/install-hooks.sh` |

缓存为空或目录不存在，说明 hook 没装：让用户在项目根目录执行

```bash
bash skills/shishisun/scripts/install-hooks.sh '<仓库上级目录>' -e '<用户本人的邮箱>'
```

（只扫该目录下一层子目录，不覆盖仓库已有 hook；邮箱决定哪些提交算这个人的工作记录。）

## 增量同步（默认流程，定时任务走这个）

1. **取待归属提交**

   ```
   sync.sh prepare
   ```

   输出四行纯文本：

   ```
   count=3
   digest=C:\Users\leo\.dsh\shishisun\digests\2026-10-21\102209.md
   since=2026-10-21
   email=leo.ze@qq.com
   ```

   - `count=0`：到此为止，只回一句「本次没有新提交」，**不要调用 MCP**。

2. **读 digest 文件**（`digest=` 那行）。它已按仓库分组，给出 `时间 + 短 hash + 提交说明 + 分支`。
   digest 只含每条提交的 **第一行（subject）**，commit body 不入库，所以别指望从 digest 里读出详细背景。

3. **拉今天的事项**

   调用 `list_items(start=今天, end=今天)`，只保留 `mine = true` 的事项。
   `mine = false` 的事项一律不写——那是别人的卡。

4. **归属**：把每个仓库的提交对到事项上，按优先级：

   1. `config.sh` 里 `shishisun_repo_project` 的映射（仓库名 → 项目名）
   2. 事项标题 / 项目名与仓库名、分支名、提交说明有明显关键词重合
   3. 一个项目今天只有一张 `mine` 事项 → 直接归给它
   4. 都对不上 → **不硬塞**，进第 6 步的「未归属」

5. **写回**（规则见下一节）。先把提交按**功能点**分组，每个功能点一条日志；同一功能点当天已有记录就用 `update_log` 加工时。写完后立刻打标记：

   ```
   sync.sh complete -d <digest 路径> -n "<一句话>"
   ```

   `complete` 会把 digest 里的提交记为已处理。**漏了这步，下一次运行会把同样的提交再写一遍日志。**

6. **回报**：一句话说明写了几条日志、写到哪些事项；未归属的提交按仓库列出条数，等用户决定怎么挂。

## 写回规则

### 跟进日志（`add_log` / `update_log`）

- **按功能点写，一个功能点一条**：一张卡一天通常 2~6 条，不是一天一条。
  - 功能点 = 一组相关提交，比如「成员列收起/展开」「屏幕共享画质」「邀请参会方页签」「运营管理原型」。
- **重叠就聚合**：分组后先算每组的提交时间区间（首条~末条）。同一模块内区间有重叠 → 合并成一条，工时只算一次；不同模块重叠时按投入占比分配，合计不超过并集时长。
- 每条 **≤20 字**（hash 不算），写这个功能点做到哪；最多 1 个 hash。
- **工时分摊**：按该功能点内提交的首末时间跨度估算（间隔 >45 分钟不计、午休不计）；当天第一轮把 09:00 起的基线加到最早的功能点上。各条合计应接近 digest 的总参考工时，差太多就按比例微调。
- **跨轮合并**：同一功能点后续还有提交 → `update_log` 把工时加上，不新增条目。
  - 映射键用 `<itemId>:<功能点>`：`sync.sh logmap get "2481:成员列"` / `sync.sh logmap set "2481:成员列" <logId>`
  - logmap 无记录、但当天已有人工日志覆盖同一功能点 → 只更新它的 `hours`，**内容不动**。
- 纯格式化、依赖升级、merge、回滚不写日志，也不计工时。
- **补录要传 `logDate`**：digest 里的提交不是今天的（补昨天的数据），`add_log` / `update_log` 必须带上该组提交的日期；否则历史工时会堆到今天。正常当日同步不传，默认今天。
- 合并后单条工时上限 12h；单事项当天总工时超过 12h，先怀疑归类重复。

### 工时（`hours`）

- digest 里每个仓库末尾都有「参考工时」：
  - **当天第一轮**：从 **09:00** 起算到该仓库最后一条提交
  - **之后各轮**：首条提交按 0.5h 打底，再累加相邻间隔
  - 相邻间隔超过 45 分钟不计；**午休 11:30–13:30 不计入**；总量封顶 8h
- 每个功能点一条日志，工时按功能点分摊后分别传入；同一功能点后续提交用 `update_log` 累加。
- 各功能点工时加起来应接近 digest 的总参考工时；不要为了凑整把某条压成 0。
- 如果明显不合理（提交挤在几分钟、跨度却有两小时），按常识压到 0.5~1h。
- 工时是参考值，宁可保守，不要当成考勤去凑数。

### 自由笔记（`notesMd`）

- 只有**结论性信息变化**才改：依赖解除、验收标准变化、里程碑状态变化、排期调整。
- 改时保留原结构（背景 / 验收标准 / 依赖与风险 / 交付物），只改对应行，不要整篇重写。
- 日常进展一律写日志，不写笔记——两者分工见 `doc/shishisun.md` 第八节。

### 状态

**不自动改状态。** 提交看起来已经满足验收标准时，在回报里建议「可以把 #123 改为已完成」，由用户拍板。

## 定时任务

schedule 是**会话级**的：新会话不会自动带上，需要重建一次。

用户说「开启自动同步」时，用 `schedule_create` 创建：

- cron：`0 9-19/2 * * 1-5`，时区 `Asia/Shanghai`（工作日 9:00–19:00 每 2 小时）
- title：`事事顺工作内容同步`
- prompt 要点：在本项目根目录用 Git Bash 跑 `sync.sh prepare`；`count=0` 只回「本次没有新提交」；否则按本节流程写日志；最后 `complete`。19:00 那轮加日总结。

已有任务用 `schedule_list` 查看、`schedule_update` 改间隔。

## 日终总结（当天最后一次运行）

当天最后一次运行（19:00 那轮）在增量同步之外，额外：

1. 汇总当天写入的日志条数与涉及事项；
2. 用 `get_log_summary(from=今天, to=今天)` 取当天工时合计，写进总结；
3. 某事项的验收标准看起来已被当天提交全部覆盖 → 给出完成建议；
4. 给用户 3~5 行日总结。

## 失败处理

| 情况 | 做法 |
|------|------|
| `count=0` 且缓存目录为空 | 提示用户跑 `install-hooks.sh <仓库上级目录>` |
| 报「检测到 WSL 的 bash」 | 当前终端不是 Git Bash。让用户在 Git Bash 里执行，不要换个解释器硬跑 |
| MCP 调用失败 | 不执行 `complete`，让下一轮重试，避免丢提交 |
| 日志部分写成功、`complete` 失败 | 手动重跑 `complete`；它按 key 去重，幂等 |
| `update_log` 报日志不存在 | 该条被删了；重新 `add_log` 并 `logmap set` 覆盖旧 id |
| 同一条提交在两个事项都说得通 | 归给投入更多的那张，另一张在回报里提一句 |
| 今天的提交都归不上事项 | 不建卡，只回报未归属清单 |

## 输出格式

每次运行结束给用户 2~4 行：

```
✅ 同步 5 条提交：#2481 融合通信（+1 条日志）、#1602 大屏 GIS（+1 条日志）
⚠️ 未归属：sc-rcs-web 3 条、oaWeb 1 条
```

没有新提交时只回一行：`本次没有新提交`。

需要权威写法（标题、验收标准、长期任务拆法）时，调用 `get_task_card_guide`；每天第一次运行读一次即可，不必每轮都读。
